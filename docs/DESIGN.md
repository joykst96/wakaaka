# 와카아카 (wakaaka) 설계

갱신: 2026-11-09 (편집기 UI: 주석 행 가중치 칸, 설명칸, ID 복사, 토스트). 결정의 근거와 확인한 사실은 작업 메모 `NOTES.md`에 있다(개인 작업 메모라 공개 저장소에는 넣지 않는다. 본문의 `NOTES.md` 언급은 그 메모를 가리킨다).

## 1. 목표

웹에서 프롬프트 와일드카드를 편집·저장·공유하고, ComfyUI 커스텀 노드가 ID로 받아 쓴다.

- 핵심은 두 가지: **편리한 편집기**, 그리고 와일드카드 안에 내 것이나 남의 와일드카드를 넣어 **이어서 조합**하는 것.
- 운영자 본인이 쓰면서 좋은 와일드카드를 서로 공유하는 것이 취지다. 사용자 모집이 목적은 아니지만, 남의 와일드카드 둘러보기, 좋아요, 인기순 정렬은 둔다.
- **모든 와일드카드는 공개다.** 비공개 기능은 없다.
- 공개 서비스. 로그인은 식별용 아이디/비밀번호만 둔다(찾기 기능 없음).

## 2. 핵심 개념

| 개념 | 설명 |
|---|---|
| 와일드카드 | 소유자가 있는 이름 붙은 항목 풀. 바뀌는 별칭이며 최신 버전을 가리킨다. ID는 base62(`0-9A-Za-z`) 12자. |
| 버전(내용) | 와일드카드 문서 하나. **불변**. ID = 정규화한 JSON의 해시 12자. 같은 내용이면 같은 ID. |
| 참조 | 문서 안에서 다른 와일드카드를 부르는 것. 대상은 항상 내 와일드카드다(아래). |
| 즐겨찾기 | 남의 와일드카드 북마크. 나만 보고 사이드바에 나타난다. 볼 때는 최신 버전, 내 것에 끌어다 넣으면 그 시점 버전을 의존성까지 내 것으로 가져온다. |
| 좋아요 | 공개 인기 표시. 인기순 정렬에 쓴다. 즐겨찾기와 별개다(좋아요만 누르거나 즐겨찾기만 할 수 있다). |
| 폴더 | 내 와일드카드를 나누어 두는 정리용 묶음. **나만 본다.** 한 단계이고, 와일드카드 하나는 폴더 하나에만 들어간다(11절 "폴더"). |
| lock | 묶음을 만들 때 확정한 `와일드카드 ID → 내용 해시` 표. 재현에 쓴다. |

### 참조 규칙

(2026-11-03 변경: 해시 스냅샷 참조를 없애고, 가져올 때 의존성까지 복사한다. 이유는 `NOTES.md`.)

1. **내 와일드카드만 참조한다**: 문서 안의 참조는 모두 내 와일드카드 ID이고 최신을 따라간다. 편집할 수 있다. 전개든 묶음이든 모든 계산은 내 와일드카드로만 한다. 그래서 lock에도 내 와일드카드 ID만 들어간다.
2. **가져오기**: 남의 와일드카드를 내 것에 넣으면, 그 시점 최신 버전을 **의존성까지 전부** 내 와일드카드로 복사한다.
   - 복사본 안의 참조(원작자의 와일드카드 ID)는 해당 복사본의 ID로 바꿔 쓴다. 항목 ID는 그대로 둔다. 그래서 가져온 직후의 결과는 같은 seed에서 원본의 그 시점 결과와 같다(하위 seed 경로는 항목 ID와 노드 번호만 쓰고 와일드카드 ID는 쓰지 않는다). 이미 있던 복사본을 다시 쓴 부분은 예외다.
   - 그 뒤로 원작자가 원본이나 그 하위를 고치거나 지워도 내 쪽은 바뀌지 않는다. 내가 복사본을 고쳐도 원본은 바뀌지 않는다.
   - 다이아몬드 의존은 한 번만 복사한다. 이미 같은 원본의 복사본이 있으면(아래 `forked_from`) 새로 만들지 않고 그것을 쓴다. 기존 복사본이 더 옛 버전이거나 내가 고친 것이어도 그대로 쓴다.
   - 복사본마다 일반 저장과 같은 검증(문법, 참조, 순환, 상한)을 거친다. 몇 개가 복사되는지 확인 창에 보여 준다.
   - 하위 참조가 없는 문서는 복사해도 내용이 같아서 내용 해시도 같다. 저장 공간은 늘지 않는다.
3. **출처와 갱신**: 복사본에는 `forked_from(원본 와일드카드 ID, 원본 내용 해시)`를 남긴다.
   - 원본에 새 버전이 나오면 복사본에 "원본에 새 버전 있음" 배지를 단다. 복사본을 고치지 않았으면 한 번에 갱신하고(새 하위 의존이 생겼으면 그것도 가져온다), 고쳤으면 diff를 보여 주고 덮어쓰기 또는 유지 중 고르게 한다. 자동 병합은 하지 않는다.
4. **이름 충돌**: 이름은 소유자 안에서 유일하므로, 복사본 이름이 내 것과 겹치면 뒤에 ` (원작자 아이디)`를 붙이고 그래도 겹치면 ` 2`, ` 3` …을 붙인다. 64자를 넘으면 원래 이름 쪽을 자른다(잠정).
5. **삭제**: 내 와일드카드의 **최신 버전**이 참조하는 와일드카드는 지울 수 없다(409와 참조하는 목록). 옛 버전의 참조는 막지 않는다. 지운 와일드카드는 조회, 이력, `/api/w/*` 모두 404이고 lock으로 고정한 요청도 마찬가지다(사용자 결정, 2026-11-03). 내용 행은 남지만 서버가 보여 주지 않는다. 옛 이미지의 재현은 노드 캐시로 한다. 같은 이름은 다시 쓸 수 있다.

## 3. 와일드카드 문서 형식

버전 하나는 JSON 문서 하나다(Postgres `JSONB`). 항목 텍스트는 원문 그대로 둔다. 태그 PK로 쪼개지 않는다. Danbooru 태그는 이름이 바뀌거나 폐기되므로, PK로 저장하면 불변 버전의 의미가 깨진다.

```json
{
  "schema": 1,
  "name": "hair color",
  "description": "기본 머리색 풀",
  "select": { "count": [1, 1], "sep": ", " },
  "items": [
    { "id": "i7Kq", "text": "red hair", "w": 3 },
    { "id": "p2Za", "text": "silver hair, ${w:<ID>} streaks, {smile|grin}" },
    { "id": "Hh40", "ref": { "wildcard": "<내 와일드카드 ID>" }, "spread": false, "w": 2 },
    { "id": "Qm8c", "ref": { "wildcard": "<가져온 복사본 ID>" }, "spread": true }
  ]
}
```

- 가중치(`w`), 개수(`count`), 구분자(`sep`)는 **필드**로 둔다. 인라인 문법은 최소로 유지한다.
- `id`: 항목마다 짧은 ID. 편집기가 부여하고 버전이 바뀌어도 유지한다. 하위 seed 경로가 이 ID에 의존한다.
- `ref`: 항목 전체가 참조인 경우. `spread: false`(기본)는 참조 대상 전체를 항목 하나로 보고, `true`는 대상의 항목들을 이 풀에 펼친다.
- **조건부 뽑기 기능은 따로 두지 않는다.** 조합으로 표현한다. 예: "미쿠 세트" 와일드카드에 `hatsune miku, ${미쿠 의상}`을 넣고, 캐릭터 풀의 항목으로 이런 세트들을 넣으면 "미쿠가 뽑히면 미쿠 의상도 뽑힌다"가 된다.
- 사용자가 이름으로 참조를 입력해도 저장할 때는 ID로 바꾼다.
- 편집기에는 한 줄에 항목 하나씩 쓰는 텍스트 보기(예: `3* red hair`)를 따로 두고 JSON과 서로 변환한다. 저장은 항상 JSON. `#`로 시작하는 줄(항목)은 주석이다(3절 "주석 항목").
- 크기 상한: 문서 하나에 항목 5,000개 또는 256KB(잠정).

### 인라인 문법 (2026-11-03 확정)

Impact Pack 문법은 따르지 않는다. 구분자는 태그 114,092개와 대조해 골랐다(`NOTES.md`).
EBNF, 읽는 순서, 경계 사례, 오류 코드는 `SPEC.md` 2절이 기준이다.

| 용도 | 편집 시 표기 | 저장 형태 |
|---|---|---|
| 참조 | `${이름}` | `${w:<ID>}` |
| 즉석 선택지 | `{a\|b\|c}` | 그대로 |
| 보기 가중치 | `{3*silver\|platinum}` | 그대로 |
| 이스케이프 | `\{` `\}` `\$` `\\`, 선택지 안에서는 `\|`도, 항목 맨 앞에서는 `\#`도 | 그대로 |
| 주석 | 항목 텍스트 맨 앞의 `#` (`# 머리색 모음`) | 그대로 |
| 예약 | `${이름 키=값}` 매개변수, `${=변수}` 변수, `${h:…}`(예전 해시 참조 자리, 2026-11-03 제거) | 미정 |

- 사용자는 이름으로 쓰고, 저장할 때 `w:` 형태로 바꾼다. 편집기는 이름이 붙은 칩으로 보여 준다. 남의 와일드카드 이름을 고르면 그 자리에서 가져오기(2절)를 한다.
- 즉석 선택지는 보기 하나를 고른다. 보기 맨 앞에 `정수*`를 쓰면 그 가중치로 고르고(`{3*silver|platinum}`은 3:1), 안 쓰면 1이다(사용자 결정, 2026-11-03). 가중치는 항목과 같은 정수 0~1,000,000이고, 소수·범위 밖·모든 보기 0은 문법 오류다. 여러 개 뽑기가 필요하면 와일드카드를 만들어 필드로 설정한다. 선택지는 중첩할 수 있고, 안에 참조를 넣을 수 있다.
  - 표기 `*`를 고른 이유: 태그 이름 0개, ComfyUI `(tag:1.2)`·NAI `1.2::tag::`·A1111·Impact Pack 어느 가중치 표기와도 겹치지 않는다. Impact Pack식 `{3::a|b}`는 선택지 맨 앞의 NAI 강조와 충돌해서 버렸다(`NOTES.md` Phase 3 "검토"). 편집기가 Impact Pack식 표기를 보면 `3*`를 안내하고, 선택지 보기별 가중치 입력 칸을 둔다.
  - 가중치를 안 쓴 선택지는 모든 보기가 1인 것과 같고, 결과도 이 문법을 넣기 전과 같다(공통 테스트 세트로 확인).
- `{}`의 NovelAI 강조 표기를 붙여 넣으면 보기 하나짜리 선택지가 되어 괄호가 사라진다. ComfyUI에서는 원래 의미 없는 표기이므로 그대로 둔다.
- 이스케이프는 위의 특수문자 앞에서만 인식한다. 그 외 백슬래시(ComfyUI `\(`, 태그 `\m/` 등)는 글자 그대로 둔다. `|`는 선택지 안에서만 특수문자다.
- **주석 항목** (사용자 요청 "행의 시작이 #로 시작하면 주석처리", 2026-11-08): 항목 텍스트가 `#`로 시작하면 그 항목은 주석이다. 목록 보기의 행 하나, 텍스트 보기의 줄 하나가 항목 하나이므로 "행의 시작" = 항목 텍스트의 첫 글자다. 정확한 규칙은 `SPEC.md` 2.7절.
  - 주석 항목은 전개에서 없는 항목처럼 다룬다: 뽑히지 않고(후보에서 빠진다. 빈 결과로 뽑히는 것이 아니다), 인라인 문법을 읽지 않아 문법 오류도 참조도 없고 의존성·순환·깊이·가중치 합 검사에 들지 않는다. 그래서 주석 항목을 더하거나 빼도 같은 seed의 결과가 같다. 문서 JSON 형식은 그대로라(새 필드 없음) 주석도 내용 해시에 들어가고, 주석만 고쳐도 새 버전이 생긴다. 주석만 있는 문서는 빈 와일드카드와 같다(저장할 수 있고 결과는 빈 문자열).
  - 첫 글자만 본다. 앞에 공백이 있는 ` # x`, 줄 중간의 `#`, 선택지 안의 `{#a|b}`는 글자다(보기 가중치 `3*`·텍스트 보기 `3* `처럼 맨 앞에 바로 와야 한다). 텍스트 보기의 `3* # x`는 가중치 표기 뒤의 항목 텍스트가 `# x`라 주석이다(가중치는 남지만 쓰이지 않는다).
  - `#`로 시작하는 태그(`#compass` 등 새 CSV 150,993개 중 3개, 옛 CSV 2개)를 항목 맨 앞에 쓰려면 `\#compass`로 쓴다. 맨 앞의 `\#`만 이스케이프이고, 다른 자리의 `\#`는 지금처럼 글자 두 개다(선택지 밖의 `\|`가 글자 두 개인 것과 같은 방식). 자동완성과 기본 와일드카드 생성기는 항목 맨 앞에 넣을 때 `\#`로 넣는다.
  - 여러 줄 항목(편집기로는 만들 수 없고 API로만 들어온다)도 항목 단위로 본다: 첫 글자가 `#`면 항목 전체가 주석이고, 둘째 줄부터의 `#`는 글자다.
  - 2026-11-03에는 `#compass` 때문에 주석 문법을 두지 않았다. 겹치는 태그가 3개뿐이고 이스케이프가 있어 사용자 요청대로 넣었다. `//`(`.hack//`)는 여전히 주석이 아니다. 와일드카드 전체 설명은 `description` 필드에 쓴다.
  - **내보내기에서는 주석 항목을 뺀다**(사용자 요청 "내보내기 할때는 주석처리한거 빼고", 2026-11-08). 사람이 복사해 가는 결과, 즉 웹 내보내기의 Impact Pack 한 줄과 와카아카 텍스트 보기 형식, API `/api/w/{id}/export`에는 주석이 나오지 않는다. 주석은 결과에 영향이 없으므로 빼도 전개 결과가 같다. 저장된 문서(편집기에서 다시 열 때, `GET /api/wildcards/{id}`)에는 주석이 그대로 남는다.
  - 내용 해시는 **주석을 포함한** 저장 문서로 계산한다(지금과 같다). 버전 ID = 저장한 내용의 해시이고(2절), 노드가 묶음 문서마다 해시를 다시 계산해 lock과 대조하므로(7절 "묶음 형식": 문서는 해시 검증을 위해 바꾸지 않는다), 노드용 묶음(`/bundle`)과 `/resolve`의 lock은 주석이 든 원본 문서와 그 해시를 쓴다. 노드는 전개 결과만 내보내므로 주석 글자가 사용자에게 나가지 않는다. 그래서 주석만 고쳐도 새 버전이 생긴다(결과는 같다).
  - 바뀌는 기존 동작: 이 변경 전에 저장된 `#`로 시작하는 항목은 주석이 되어 뽑히지 않는다. 주석이 없는 문서는 결과도 해시도 그대로다. 확인한 범위는 `NOTES.md` 2026-11-08 "주석 항목".
- 분류: 고정 목록에서 원하는 사람만 고른다(중복 가능, 선택 안 해도 됨). 목록은 `danbooru-tag` TAXONOMY의 대분류 이름을 바탕으로 줄인 것이다(2026-11-03 확정, 저장 순서 = ID 1~13): 캐릭터·작품, 작가·화풍, 인물·관계, 신체·머리카락, 얼굴·표정, 의복·장신구, 행동·자세, 사물, 장소·배경, 구도·시점, 상황·주제, 프리셋·조합, 기타. 분류를 바꿔도 새 버전이 생기지 않는다.
- 와일드카드 이름은 같은 소유자 안에서 유일하다(대소문자 무시, 지운 것 제외). `{ } $ \ | = :`는 이름에 쓸 수 없다(잠정). API 저장에서는 이름이 필수이고, 코드 포인트 1~64자, 앞뒤 공백은 거부한다(고쳐 주지 않는다. 문서를 바꾸면 해시가 바뀌므로). 와일드카드 행의 이름은 최신 버전 문서의 `name`이다(사용자 결정, 2026-11-03).
- 정규식 치환이 아니라 진짜 파서로 구현해서, 편집기가 오류 위치를 표시할 수 있게 한다.

### 매개변수 (예약)

빈칸을 가진 와일드카드(예: "의상(색=?)")를 만들고, 부르는 쪽이 값을 채운다. 값은 **명시적인 매개변수로만** 넘긴다. 상위 변수가 하위로 저절로 흘러 들어가지 않게 한다. 남의 와일드카드가 우연히 같은 변수 이름을 써서 엉뚱한 값을 받는 일을 막기 위해서다.

## 4. 전개 의미론

같은 (루트, lock, seed)라면 TS 전개기와 Python 전개기의 결과가 **글자 하나까지 같아야** 한다. 두 구현은 `packages/core/conformance`의 공통 테스트 세트(입력, seed, 기대 출력)로 검증한다.

- 절차, 난수, 하위 seed, 오류 코드의 정확한 정의는 `SPEC.md` 3~6절이 기준이다.
- 풀에서 `count` 범위 안의 개수를 정하고, 가중치에 비례해 **중복 없이** 뽑아 뽑힌 순서대로 `sep`으로 잇는다.
  - 가중치는 상대값이고 **정수**(0~1,000,000)다. `w = 0`은 뽑히지 않는다. spread를 펼친 후보가 하나 이상인데 가중치 합이 0이면 저장할 때 오류로 처리한다. 후보가 없는 문서(빈 와일드카드)는 저장할 수 있다. spread 대상을 고쳐서 그것을 펼치는 쪽의 합이 0이 되면 대상 저장은 받고 경고한다(사용자 결정, 2026-11-03).
  - 문서 안 항목 순서는 결과에 영향이 없다(후보를 항목 ID 순으로 정렬해서 뽑는다). 편집기에서 항목을 옮겨도 결과가 그대로다.
  - 뽑힌 항목의 결과가 빈 문자열이면 구분자도 붙이지 않는다. 빈 항목을 "없음" 보기로 쓸 수 있다.
  - 전개가 끝난 최종 결과에서 공백뿐인 쉼표 조각을 지우고 앞뒤 공백을 지운다(`1girl, , standing` → `1girl, standing`, `SPEC.md` 4.4). 0개일 수 있는 참조를 쉼표 사이에 그냥 둘 수 있다.
  - `spread` 항목에는 `w`를 쓰지 않는다. 펼친 항목은 자기 가중치를 그대로 쓰고, 대상의 `count`와 `sep`은 무시한다.
  - Impact Pack처럼 "합이 1 이하이면 전부 출력하는" 동작은 두지 않는다.
- 개수가 항목 수보다 크면 항목 수로 자른다.
- 전개기는 문자열과 함께 **출처 범위** 목록(시작, 끝, 와일드카드 ID 또는 해시, 항목 ID, 정의는 `SPEC.md` 4.5절)을 돌려준다. 편집기 미리보기의 출처 강조에 쓴다. 공통 테스트 세트는 문자열을 필수로 비교하고, 출처 범위는 TS 쪽에서만 검사한다.
- **하위 seed** = `H(seed, 경로)`. 경로는 루트부터 이어지는 (항목 ID, 참조 위치)의 연결이다.
  - 해시가 아니라 항목 ID를 쓰는 이유: 한 항목의 텍스트를 고쳐도 다른 항목의 선택이 유지된다.
  - 하위 와일드카드를 갱신하면 그 아래의 선택만 바뀐다.
- 난수는 SplitMix64, `H`는 `derive(s, 라벨) = mix64(s ⊕ mix64(FNV-1a64(라벨)))`를 경로를 따라 접은 것이다(2026-11-03 결정, `SPEC.md` 6절). 경로 라벨은 `item:<항목 ID>`, `pos:<노드 번호>`, `select`.
- 최대 깊이와 묶음 전체 크기에 상한을 둔다(잠정: 깊이 16, 묶음 2MB, 전개 횟수 10,000).
  - 전개기는 깊이, 순환, 없는 참조, 문법 오류를 seed와 무관하게 전개 전에 검사한다. 저장 때 깊이 초과를 경고만 하고 저장했더라도, 그 문서의 전개는 항상 `E_DEPTH`로 실패한다. seed에 따라 가끔 실패하는 것보다 낫다.

## 5. 저장과 수정 전파

저장할 때 다음 순서로 검증한다. 0단계와 마지막 저장 방식은 9절 "입력과 저장"을 따른다.

0. 본문 크기 제한(파싱 전), JSON 파싱, 문자열 검사(U+0000·짝 없는 서로게이트 거부), 모르는 필드 거부
1. 스키마와 인라인 문법 파싱
2. 참조 대상 확인: 내 와일드카드 ID여야 한다.
3. 순환 검사. 모든 참조가 "내 와일드카드 최신"이므로 내 와일드카드 엣지 전체를 검사한다.
4. 깊이와 크기 상한
5. 영향 분석: 역방향 엣지로 이 와일드카드를 쓰는 내 와일드카드를 찾아 다시 검증하고, 상한 초과 같은 문제를 경고로 보여 준다.
6. 서버가 정규화(JCS)한 JSON으로 내용 해시를 계산하고 저장한다. 같은 해시가 이미 있으면 저장된 내용과 바이트 단위로 비교하고, 다르면(해시 충돌) 거부한다.
7. `wc_ref` 엣지 기록

스키마·문법 오류, 없는 참조, 순환이 있으면 저장을 거부한다. 저장된 문서는 항상 파싱되고 참조가 해결된다. 나머지 문제(상한 초과, 영향 분석 경고)는 경고만 하고 저장한다.

## 6. 데이터 모델 (PostgreSQL, 초안)

```sql
owner        (id, username UNIQUE /* 대소문자 무시, 지운 계정 포함 */, pw_hash /* argon2id */, created_at, deleted_at NULL /* 관리자 계정 삭제 */)
session      (token_hash PK /* 쿠키 토큰의 sha256 */, owner_id, created_at, expires_at)

wc_content   (hash CHAR(12) PK, doc JSONB, size /* 정규화 JSON 바이트 수 */, created_at)  -- 내용, 중복 제거
wildcard     (id CHAR(12) PK, owner_id, name /* UNIQUE(owner_id, lower(name)) WHERE deleted_at IS NULL */, latest_seq,
              like_count /* wc_like와 같은 트랜잭션에서 갱신 */,
              categories SMALLINT[] /* 고정 분류, 중복 선택, GIN 색인. 버전이 아니라 와일드카드에 붙는다 */,
              forked_from_wildcard NULL, forked_from_hash NULL,
              folder_id NULL /* 0007. FK (owner_id, folder_id) → wc_folder (owner_id, id) ON DELETE SET NULL (folder_id) */,
              created_at, deleted_at NULL)                               -- 바뀌는 별칭
wc_version   (wildcard_id, seq, hash, created_at, PK(wildcard_id, seq))  -- 이력
wc_ref       (src_hash, item_id, target_wildcard_id)                     -- 내용에서 파생. 참조는 항상 내 와일드카드
favorite     (owner_id, wildcard_id, created_at)
wc_like      (owner_id, wildcard_id, created_at, PK(owner_id, wildcard_id))  -- 계정당 1회, 자기 것은 불가
wc_folder    (id CHAR(12) PK /* base62 무작위 */, owner_id, name /* UNIQUE(owner_id, lower(name)) */, created_at,
              position INT /* 0008. 사용자가 정한 순서. UNIQUE(owner_id, position) DEFERRABLE, 빈 번호 허용 */,
              UNIQUE(owner_id, id) /* 위 복합 FK의 대상 */)                -- 0007. 나만 보는 폴더(11절 "폴더"). 지우면 행을 지운다

tag          (id, name UNIQUE, category, post_count,
              description /* CSV 원문 그대로 */, body /* 분류 표시·키워드를 뗀 본문(화면용) */,
              keywords TEXT[], other_names TEXT[], major_category NULL, minor_category NULL, is_deprecated,
              name_key /* 밑줄·공백을 뺀 소문자. 영문 검색 */, ko_text /* 키워드 + 본문 소문자. 한국어 부분 일치 */)
tag_keyword  (tag_id, key /* 공백을 뺀 소문자 */, kind /* 0 키워드 전체·한글 별명, 1 키워드 낱말 */, post_count /* tag 값 복사, 0006 */)  -- 한국어 접두 검색. 색인 (key, kind, post_count desc, tag_id)
tag_alias    (alias_name, tag_id)   -- Danbooru active alias. 지금 데이터에 없어 비어 있다(사용자 결정, 2026-11-04)
tag_import   (id, file_name, file_sha256, file_size, row_count, columns, stats JSONB, imported_at)  -- 태그 데이터 버전
```

- 내용 해시: 정규화한 JSON(RFC 8785 JCS) → sha256 → base62 앞 12자(약 71비트). 정확한 정의(키 순서, 수 표기, base62 자릿수)는 `SPEC.md` 7절, 벡터는 `conformance/hash.json`.
- 와일드카드 ID와 내용 해시는 표기로 구분하지 않는다. URL 경로와 노드 입력은 항상 와일드카드 ID만 받고, 해시는 lock 값과 묶음 `docs` 키에만 나온다. 특정 버전은 lock이나 `?v=<seq>`로 고른다(사용자 결정, 2026-11-03). 해시를 입력으로 받을 일이 생기면 그때 접두사를 정한다.
- 폴더 소속(2026-11-08): `wildcard.folder_id`의 FK가 `(owner_id, folder_id)` 쌍이라 **남의 폴더에 넣는 것은 DB가 막는다**(서비스도 먼저 검사한다). 폴더를 지우면 FK가 `folder_id`만 NULL로 바꾼다(Postgres 15부터의 열 목록 `SET NULL`). 소속은 버전·내용·해시와 상관없다.
- 의존 묶음은 재귀 CTE 한 번으로 가져온다(`UNION`으로 다이아몬드 의존 중복 제거).

```sql
WITH RECURSIVE deps(wildcard_id, hash) AS (
  SELECT $1::char(12), $2::char(12)          -- 루트 와일드카드와 그 버전 해시
  UNION
  SELECT w.id, v.hash
  FROM deps d
  JOIN wc_ref r     ON r.src_hash = d.hash
  JOIN wildcard w   ON w.id = r.target_wildcard_id
  JOIN wc_version v ON v.wildcard_id = w.id AND v.seq = w.latest_seq
)
SELECT d.wildcard_id, d.hash, c.doc FROM deps d JOIN wc_content c USING (hash);  -- lock과 docs를 한 번에
```

- 태그 데이터 원천(사용자 결정, 2026-11-08 교체): Hugging Face [`mengod-hf/danbooru-tags-kr`](https://huggingface.co/datasets/mengod-hf/danbooru-tags-kr)의 통합본 `danbooru-tags-kr-2026-11-04.csv`(150,993행). 한국어 번역·설명·분류는 CC BY-SA 4.0이라 README와 사이트 안내에 출처와 라이선스를 적는다. 파일은 저장소에 넣지 않고 이 PC의 `data/`(git 무시)에 둔다. 전에 쓰던 `danbooru-tag` 프로젝트의 `danbooru-tags.csv`(헤더 있는 형식)도 계속 읽을 수 있다. 그쪽 6열 최종본이 나오면 다시 고를 수 있다.
- 태그 가져오기(Phase 5, 2026-11-04, 근거는 `NOTES.md` Phase 5):
  - **열 이름으로 읽는다.** `name`, `category`, `post_count`는 필수, `description`, `major_category`, `minor_category`, `keywords`, `other_names`는 있으면 쓰고 없으면 비운다. 모르는 열 이름은 무시하고 보고한다.
  - **헤더 없는 형식**(mengod-hf): 첫 행에 `name` 열이 없으면 헤더가 없다고 보고 `name,category,post_count,description` 4열 고정으로 읽는다(첫 행도 데이터). 이 형식만 다음을 더 한다. 태그 이름의 공백을 밑줄로 되돌린다(이 형식은 Danbooru 이름의 밑줄을 모두 공백으로 적는다. 되돌려도 겹치는 이름이 없고, 옛 CSV와 겹치는 이름은 모두 같은 이름이 된다. NOTES 2026-11-08). 키워드 맨 앞의 묶음 표시(`<교복>`, `<캐릭터>`)는 꺾쇠만 떼어 키워드로 둔다(school_uniform의 `<교복>`처럼 그 태그를 부르는 이름인 경우가 많아, 빼면 `교복` 검색이 school_uniform을 못 찾는다. `캐릭터`처럼 넓은 것은 같은 키워드끼리 post_count 순이라 해가 적다). 설명 맨 앞의 한 단계 표시 `[작가]`도 본문에서 뗀다. 대분류 앞뒤 공백은 지운다.
  - 예외 하나(헤더 있는 형식): 옛 `danbooru-tags.csv`는 헤더가 4열인데 뒤쪽 42,947행이 이름 없는 다섯째 열(위키 other_names, `|` 구분)을 가진다. 헤더에 `other_names`가 없고 행이 헤더보다 정확히 한 칸 많으면 그 칸을 `other_names`로 읽는다. 그 밖의 열 수 불일치는 오류로 멈춘다.
  - 설명이 `[대분류 > 소분류] 본문 키워드: a, b`이면 `body`와 `keywords`를 뽑는다. 대괄호 분류는 예전 체계라 `major_category`·`minor_category`에 넣지 않는다(두 열은 CSV에 그 열이 있을 때만 채운다). 원문은 `description`에 그대로 둔다.
  - 다시 돌려도 된다: 한 트랜잭션에서 태그 표들을 비우고 새로 넣는다(읽는 쪽은 커밋 전까지 옛 데이터를 본다). 파일 SHA-256이 마지막 가져오기와 같으면 건너뛴다(`--force`로 강제). `tag_import`에 파일 이름·해시·크기·행 수·열 목록·시각을 남긴다. 와일드카드 문서는 태그 ID를 쓰지 않으므로(3절) 태그를 다시 넣어도 저장 데이터에 영향이 없다.
  - other_names는 별명이지 정규 이름 병합 근거가 아니다(`danbooru-tag` 규칙). `tag_alias`에 넣지 않고, 한글이 든 것만 한국어 검색 키워드처럼 쓴다.

| `POST /api/wildcards/{id}/import` | 가져오기: 남의 와일드카드를 의존성까지 내 것으로 복사. 만들거나 다시 쓴 복사본 목록을 돌려준다 |
| `DELETE /api/wildcards/{id}` | 별칭 내리기. 내용은 남긴다. |
| `GET/POST /api/favorites`, `DELETE /api/favorites/{id}` | 즐겨찾기. 남의 와일드카드만 |
| `GET/POST /api/folders`, `PUT/DELETE /api/folders/{id}` | 내 폴더 목록(사용자가 정한 순서, 폴더마다 든 와일드카드 ID), 만들기(`after`: 이 폴더 바로 다음에. 없으면 맨 끝), 이름 바꾸기, 지우기. 로그인 필요, 내 것만(11절 "폴더") |
| `POST /api/folders/move` | 내 와일드카드 여러 개를 폴더 하나로(`folder: null`이면 "폴더 없음"으로) 옮긴다 |
| `POST /api/lookup` | 여러 ID의 메타데이터를 한 번에 조회 (편집기 칩용, N+1 방지) |
| `GET /api/tags/suggest?q=` | 태그 자동완성 (영문, 한국어). 아래 "태그 자동완성" |
| `POST /api/tags/lookup` | 이름 여러 개가 태그 DB에 있는지 한 번에(편집기 표기 lint용, N+1 방지) |
| `GET /api/explore?q=&cat=&sort=popular\|recent` | 둘러보기와 검색. 기본은 `popular`(누적 좋아요). `q`는 이름·설명 검색(`pg_trgm`), `cat`은 고정 분류(여러 개면 하나라도 포함). 가져온 복사본은 내용을 고친 것만 나온다(사용자 결정 2026-11-03, 2026-11-04 변경. 11절) |
| `GET /api/users/{username}/wildcards` | 사용자별 와일드카드 목록(복사본 포함, 원작자 표시) |
| `PUT/DELETE /api/wildcards/{id}/like` | 좋아요, 취소 (로그인 필요) |
| `GET /api/w/{id}/bundle` | 노드 로컬 모드: 닫힌 묶음과 lock |
| `GET /api/w/{id}/resolve?seed=&lock=` | 노드 서버 모드: 전개된 문자열과 lock |
| `GET /api/w/{id}/meta` | 노드 표시용: 이름, 소유자, 최신 버전 번호 |
| `GET /api/w/{id}/export?format=impact` | Impact Pack 와일드카드 노드용 프롬프트 한 줄과 경고(아래 "Impact Pack 내보내기"). `format`은 enum |

와일드카드 조회와 `/api/w/*`는 로그인 없이 쓸 수 있다(모두 공개). 폴더 정보는 `/api/folders`에만 나오고, 내 목록(`GET /api/wildcards`)을 포함한 다른 응답에는 넣지 않는다. lock이 있는 요청은 결과가 고정이라 Cloudflare에서 캐시한다(Cache Rule, 10절 "운영 배포").

### 태그 자동완성 (Phase 5, 2026-11-04)

- `q`에 한글이 있으면 한국어 검색, 없으면 영문 검색. 앞뒤 공백을 지우고 비면 빈 목록. 64자, 문자열 검사(9절). 결과는 최대 20개, 각 `{name, category, postCount, body, keywords}`.
- 영문: 이름에서 밑줄·공백을 빼고 소문자로 비교한다(`long h`, `long_h`, `longh`가 같다). 이름 키 접두 일치를 먼저 post_count 순으로, 모자라면 3글자 이상일 때 부분 일치를 post_count 순으로.
- 한국어: 순위는 키워드 전체가 같음(공백 무시) → 키워드 접두 → 키워드 낱말 접두 → (3글자 이상) 키워드·본문 부분 일치, 같은 단계는 post_count 순. 한글 other_names는 키워드와 같이 친다. 1~2글자는 trgm이 색인을 못 써서 키워드 접두 표(`tag_keyword`)로만 찾는다(실측 `NOTES.md`).
  - 구현(2026-11-08): 단계마다 post_count 순으로 2×20개만 고르고 합친다(한 문장). 키워드 단계는 `tag_keyword` 색인만 읽고, 부분 일치는 키워드 단계가 20개를 못 채웠을 때만 돈다. 모두 모아 정렬하던 처음 구현은 새 CSV에서 `캐릭터`(키워드·본문 5만 개 일치)가 266ms였다. 처음 구현은 대조 기준으로 남기고 실제 CSV 질의 150개 이상에서 결과가 같음을 테스트한다.
- LIKE 패턴은 `\ % _`를 이스케이프한다. 태그 데이터는 가져오기 때만 바뀌므로 응답에 `Cache-Control: public, max-age=300`을 붙인다. 웹은 같은 `q`의 결과를 메모리에 둔다.

### 묶음 형식

```json
{
  "format": 1,
  "root": "<루트 해시>",
  "lock": { "<와일드카드 ID>": "<해시>" },
  "docs": { "<해시>": { "schema": 1, "items": [ ] } }
}
```

- 문서는 해시 검증을 위해 바꾸지 않는다. 주석 항목(3절)도 빼지 않는다(내보내기와 다르다. 노드는 전개 결과만 내보낸다). 문서 안의 참조는 `lock`으로 해시를 찾는다. 묶음의 와일드카드는 모두 루트 소유자의 것이다(가져온 복사본 포함).
- `lock`에는 **루트 와일드카드도 들어간다**(`lock[루트 ID] = root`). 루트 버전까지 고정해야 재현되기 때문이다. 순환이 없으므로 문서 안에서 루트를 참조하는 일은 없어 전개 결과에는 영향이 없다(사용자 결정, 2026-11-03).
- `resolve`의 `lock` 쿼리는 `ID:해시`를 `,`로 이은 것이다(ID 순 정렬, base62와 `:` `,`만 써서 이스케이프가 필요 없다). 루트가 들어 있어야 한다. 서버는 각 쌍이 그 와일드카드의 실제 버전인지 확인하고, 루트에서 닿는 참조가 lock에 없으면 최신으로 채우지 않고 오류를 낸다. 닿지 않는 항목은 무시한다. `lock`이 없으면 최신으로 전개한다. 응답의 lock은 닿는 항목만 담는다.
- 서버는 응답 전에 모든 참조가 묶음 안에서 해결되는지(닫혀 있는지) 확인한다.
- 노드는 받은 문서마다 해시를 다시 계산해 ID와 대조한다. 모르는 `format`이면 노드 업데이트를 안내한다.
- 참조 자리에 내용을 텍스트로 끼워 넣지 않는다. 다이아몬드 의존이 폭발하고, `spread`와 가중치 의미가 사라지고, 하위 seed 경로가 깨지기 때문이다.

## 8. ComfyUI 노드

노드 `Wakaaka Wildcard` 하나 (2026-11-03 확정).

| 위젯 | 내용 |
|---|---|
| `wildcard` | 와일드카드 ID. 웹 페이지 주소를 붙여 넣어도 ID를 뽑아낸다. 아래에 "이름 · 소유자 · v번호"를 표시한다. |
| `seed` | ComfyUI 표준 seed 위젯(실행 후 고정/증가/무작위) |
| `follow_latest` | 켜짐(기본): 큐에 넣을 때마다 최신 lock으로 갱신. 꺼짐: 저장된 lock을 그대로 쓴다. |
| `text` | 읽기 전용. 큐에 넣을 때 전개 결과가 채워진다. |
| `lock` | 접힌 값. "v12에 고정"처럼만 보인다. |

출력은 `text`(STRING) 하나이고, "웹에서 열기" 버튼이 있다.

### 동작 (큐에 넣을 때)

`PromptServer.instance.add_on_prompt_handler`로 훅을 등록한다(Impact Pack `populate`와 같은 방식, `NOTES.md`).

1. 훅이 노드를 찾는다. `follow_latest`가 켜져 있으면 최신 lock을 받는다.
2. lock과 seed로 전개해 `text`를 채운다. 로컬 모드는 캐시된 묶음으로 직접 전개하고, 서버 모드는 `/resolve`를 호출한다.
3. `lock`과 `text`를 실행 입력(`prompt`)과 PNG용 워크플로(`extra_pnginfo`)에 써 넣고, `send_sync`로 화면 위젯을 갱신한다.
4. 실행 시에는 채워진 `text`를 그대로 내보낸다.

모든 이미지에 그때의 lock과 결과가 남는다. 그래서 `follow_latest`가 기본으로 켜져 있어도 재현할 수 있다.

구현에서 정한 것 (Phase 4, 2026-11-03, 근거는 `NOTES.md` Phase 4):

- lock 위젯 값은 JSON `{"lock":{ID:해시},"v":버전}`이다. `v`는 "v12에 고정" 표시용이고 `/meta`로 얻는다. `follow_latest`를 꺼도 저장된 lock이 지금 ID의 것이 아니면 최신으로 받는다.
- 훅이 채우지 못하면(없는 ID, 서버 오류) 실행할 때 노드 오류로 낸다. 옛 text가 조용히 나가지 않게 한다.
- `wildcard`·`seed` 등이 링크로 들어오면 훅은 값을 모르므로 실행할 때 채우고, 그때 PNG 워크플로(hidden `EXTRA_PNGINFO`)와 화면을 고친다.
- 화면 갱신(`send_sync`)은 큐에 넣은 브라우저에만 보낸다.
- 서브그래프 안의 노드는 워크플로의 서브그래프 정의를 고친다(같은 서브그래프 인스턴스끼리 공유한다).

### 설정과 그 밖의 규칙

- **로컬/서버 모드와 서버 주소는 ComfyUI 설정에 둔다.** 노드 위젯이 아니다. 두 모드는 결과가 같으므로 워크플로마다 다를 이유가 없다. 테스트 때는 주소를 테스트 서버의 터널 주소나 LAN 주소(`http://<서버>:8490`)로 바꾼다.
  - 기본값은 서버 모드, `https://wakaaka.baepoyong.com`(사용자 결정, 2026-11-03. 2026-11-04 이 주소를 운영 주소로 정해 바꾸지 않는다). 주소는 http(s)만 받는다.
  - 훅은 요청한 사용자를 모르므로 `default` 사용자의 설정을 읽는다(`--multi-user`의 한계).
- 노드의 HTTP 요청은 자기 User-Agent(예: `wakaaka-comfy-node/<버전>`)를 보낸다. Python `urllib` 기본값 `Python-urllib/…`은 Cloudflare가 error 1010으로 막는다(`NOTES.md` Phase 2, 2026-11-03 실측).
- 훅은 동기 함수이므로 네트워크 호출에 짧은 타임아웃(약 3초)을 두고 캐시를 먼저 본다. 서버에 연결할 수 없으면 캐시로 전환하고, 캐시도 없으면 노드에 "와일드카드를 찾을 수 없음: ID" 같은 분명한 오류를 낸다.
- 이름 표시용 조회는 노드의 Python 경로(`/wakaaka/meta`)를 거친다. 브라우저에서 wakaaka 서버를 직접 부르면 CORS에 막힌다.
- 캐시는 해시 단위로 ComfyUI의 `user/` 아래에 둔다. 노드를 업데이트해도 지워지지 않게 하기 위해서다. lock과 캐시만 있으면 오프라인에서 재현할 수 있다.
  - 위치는 `user/__wakaaka/cache`(HTTP로 읽히지 않는 시스템 사용자 폴더). 읽을 때도 해시를 다시 확인한다.
  - 서버 모드도 성공한 뒤 그 버전의 묶음을 백그라운드로 받아 캐시하고, 서버에 연결할 수 없으면 캐시로 로컬 전개한다(사용자 결정, 2026-11-03). `follow_latest`가 켜져 있으면 마지막으로 받은 최신 lock을 쓴다.
  - 로컬 모드에서 고정 lock의 문서가 모두 캐시에 있으면 서버를 부르지 않는다. 옛 버전이라 `/bundle`(최신)로 받을 수 없으면 `/resolve`로 받는다.
  - 연결에 실패하면 10초 동안 그 서버를 부르지 않는다(훅이 ComfyUI 이벤트 루프를 막으므로).
- Python 전개기는 노드용으로 따로 둔다(노드 저장소 `joykst96/comfyui-wakaaka`의 `wakaaka_node/expander.py`). 참조 모델은 공통 테스트 세트의 독립 기준으로 남긴다(사용자 결정, 2026-11-03).
- 앞뒤 고정 텍스트를 붙이는 기능은 두지 않는다. 품질 태그를 포함한 "장면 프리셋" 와일드카드를 웹에서 만들거나, KJNodes의 문자열 연결 노드를 쓴다. 네거티브는 노드를 하나 더 놓는다.
- 큐를 여러 개 넣으면 ComfyUI가 각각 따로 실행한다. 대량 생성에는 묶음을 한 번만 받는 로컬 모드를 권장한다.
- 출시 순서: 서버 모드만 있는 노드 → 로컬 전개기(공통 테스트 세트 통과 후).
- 묶음을 워크플로에 통째로 넣는 옵션은 나중 기능이다(13절).
- Impact Pack(GPL-3.0) 코드는 복사하지 않는다. 훅 사용 방식만 참고한다.

## 9. 계정과 보안

- 비밀번호는 argon2id로 해시한다. 세션은 httpOnly + Secure + SameSite 쿠키. 찾기 기능은 없다는 것을 가입할 때 분명히 알린다.
- 아이디는 대소문자를 구분하지 않고 유일하다. 형식은 `[A-Za-z0-9_-]` 3~32자이고 가입할 때 쓴 대소문자를 표시용으로 남긴다. 비밀번호는 8~256자이고 문자 종류 규칙은 없다(사용자 결정, 2026-11-03).
- 속도 제한(2026-11-04). Cloudflare가 Free 플랜이라 속도 제한 규칙은 1개, 기간·차단 10초, 식에는 경로만 쓸 수 있다(메서드는 Business부터, `NOTES.md` Phase 6). 같은 경로를 읽기(GET)와 쓰기(PUT·DELETE)가 같이 쓰므로 쓰기는 앱에서 센다(사용자 결정). 읽기는 제한하지 않는다.
  - Cloudflare: `/api/auth/login`, `/api/auth/signup`, `/api/auth/password`에 IP당 10초 5회, 넘으면 10초 차단.
  - 앱(메모리, 프로세스 하나): 쓰기(`/api/` 아래 POST·PUT·DELETE. 로그아웃과 읽기용 POST인 `/api/lookup`·`/api/tags/lookup`은 뺀다) 계정당 1분 60회·IP당 1분 120회, 가입 IP당 1시간 5회, 로그인·비밀번호 변경 IP당 10분 30회(잠정). 넘으면 429 `E_RATE_LIMIT`과 `Retry-After`(초).
  - IP는 `TRUST_CF_IP=1`이면 `CF-Connecting-IP`, 아니면 소켓 주소다. 운영은 앱이 `127.0.0.1`에만 열려 있어 터널(cloudflared)로만 들어오므로 이 헤더를 믿는다. 재시작하면 셈이 비워진다.
- 입력과 출력의 인젝션 방어는 아래 "입력과 저장"을 따른다.
- 노출: 둘러보기 목록이 있으므로 스팸이 노출을 노리고 올 수 있다. 다음으로 막는다.
  - 기본 정렬은 인기순이다. 좋아요가 없는 스팸은 위로 올라오지 않는다. "최신순"을 둔다면 기본값으로 하지 않는다.
  - 페이지는 `noindex`이고 서버 렌더링을 하지 않는다. 검색엔진 노출을 노리는 스팸에게 얻을 것이 없게 한다.
  - 좋아요는 로그인이 필요하고 계정당 한 번이다. 부계정 조작은 가입 속도 제한으로 억제하는 정도로 받아들인다.
- 신고 기능은 두지 않는다(사용자 결정, 2026-11-04). 문제가 되는 와일드카드는 운영자가 직접 처리한다.
- 관리(사용자 결정, 2026-11-04): 웹과 API에는 관리 권한이 없다. 서버에서 `docker compose exec`로 돌리는 CLI(`apps/api/src/admin.ts`, 이 PC에서는 `deploy/prod-admin.sh`)만 쓴다. 권한은 "서버에 ssh로 들어올 수 있는가"다. 바꾸는 명령은 기본이 드라이런(할 일만 보여 줌)이고 `--yes`를 줘야 실행한다. 인자는 와일드카드 ID(base62 12자)와 아이디 형식만 받는다.
  - **와일드카드 강제 삭제**: 소유자와 상관없이 지운다. 지운 뒤의 규칙은 2절 5항과 같다(404). 참조는 같은 소유자 안에만 있으므로(2절 1항), 그 소유자의 다른 와일드카드 최신 버전이 (건너서라도) 참조하면 일반 삭제의 409 대신 **그것들도 함께 지운다**. 함께 지울 목록을 먼저 보여 준다. 남이 가져간 복사본은 그 사람의 것이라 그대로 둔다.
  - **계정 삭제**: 그 계정의 와일드카드를 모두 지우고, 세션·즐겨찾기·좋아요·폴더를 지운다(좋아요를 받은 쪽의 수도 내린다). 로그인은 없는 아이디와 같은 401, 사용자 페이지는 404다. 아이디는 다시 가입할 수 없게 남긴다. 계정 되살리기는 없다.
  - **되살리기**: 지운 와일드카드를 되돌린다. 함께 지운 것은 ID를 여러 개 줘서 함께 되살린다. 같은 이름이 그 사이 다시 쓰였거나, 되살린 것의 최신 버전이 참조하는 와일드카드가 지운 채로 남거나, 계정이 지워졌으면 거부한다.
  - 계정 정지는 두지 않는다.
- 인프라: Cloudflare Tunnel → `app`만 노출. 운영 앱은 `127.0.0.1`에만 연다. Postgres는 내부 네트워크에만 둔다. 집 IP와 포트를 노출하지 않는다.

### 입력과 저장 (인젝션 방어, 2026-11-03)

같은 JSON을 JS, Python, Postgres가 서로 다르게 읽는다(`NOTES.md` 실측). 그래서 **받은 텍스트를 그대로 저장하지 않고, 검증한 결과를 서버가 다시 직렬화해서 저장한다.** 이것이 아래 규칙들의 바탕이다.

1. **검증한 것만 저장한다.** 순서: 본문 크기 제한(파싱 전, 문서 256KB) → `JSON.parse` → zod 엄격 스키마(모르는 필드는 거부, 타입·범위 검사) → 문자열 검사 → 문법 파싱 → 정규화(JCS)한 JSON을 다시 만든다. 해시 계산, DB 저장, 묶음 응답은 모두 이 정규화 결과를 쓴다.
   - 막는 것: 중복 키, 언어마다 다르게 읽히는 숫자(`1e400`은 Postgres에서 정확한 큰 수, JS에서 `Infinity` → 다시 직렬화하면 `null`, Python에서 `inf`), 모르는 필드에 숨긴 내용, `__proto__` 같은 키.
2. **문자열 검사**: 모든 문자열은 올바른 유니코드여야 한다. 짝 없는 서로게이트를 거부하고(`String.prototype.isWellFormed()`), U+0000을 거부한다. 탭, 줄바꿈, CR을 뺀 나머지 C0 제어문자도 거부한다(잠정).
   - 이유: Postgres jsonb는 `\u0000`과 짝 없는 서로게이트를 오류로 거부해 500 오류가 난다. Python은 짝 없는 서로게이트를 UTF-8로 바꾸지 못해 노드의 해시 재계산이 깨진다.
3. **SQL**: Kysely 쿼리 빌더와 파라미터 바인딩만 쓴다.
   - `sql.raw`, `sql.lit`, `sql.ref`(식별자)에 사용자 입력을 넣지 않는다.
   - 정렬·필터처럼 식별자가 되는 값은 zod enum 화이트리스트로 받는다(`sort=popular|recent`).
   - `LIKE`/`ILIKE` 검색어는 `%`, `_`, `\`를 이스케이프한다.
   - 문서 JSON 내부를 사용자가 준 키로 SQL 경로 연산자(`->`, `#>`) 조회하지 않는다.
4. **프로토타입 오염**: 사용자 JSON을 재귀 병합하지 않는다(직접 만든 merge, `lodash.merge`, 사용자 객체에 `Object.assign` 금지). 스키마를 통과한 결과 객체만 쓴다. `JSON.parse`는 `__proto__`를 일반 키로 만들고, 단순 재귀 병합은 전역 `Object.prototype`을 오염시킨다(실측).
5. **내용 해시**: 해시는 항상 서버가 계산하고, 클라이언트가 보낸 해시는 믿지 않는다.
   - 내용 테이블은 사용자 사이에 공유된다. 그래서 `ON CONFLICT DO NOTHING`으로 넘기지 않고, 같은 해시가 있으면 저장된 정규화 JSON과 바이트 비교해서 다르면 거부하고 기록한다(5절 6단계).
   - 이유: 12자 base62는 약 2^71.5라 남의 기존 해시를 노리는 것(역상)은 불가능하다. 하지만 공격자가 두 문서를 다 만드는 충돌은 약 7×10^10번 해시로 된다(Node 한 코어 약 30시간, GPU로는 몇 초~몇 분).
   - 공격 시나리오: 악성 A를 먼저 저장 → 같은 해시의 무해한 B를 공개 → 누가 B를 가져오면(하위 참조 없는 문서는 그대로 복사되어 해시가 같다) 그 사람의 버전이 A를 가리킨다. 노드의 해시 재검증도 12자 충돌은 못 잡으므로, 서버 저장 단계가 유일한 방어선이다.
6. **권한이 걸린 필드**: `owner_id`, `forked_from`, `latest_seq` 등은 세션과 서버 로직만 정한다. 요청 본문에서 받지 않는다(mass assignment 방지). 수정·삭제는 소유자를 확인한다.
7. **출력(XSS)**: React 기본 이스케이프만 쓴다. `dangerouslySetInnerHTML`·`innerHTML`, 사용자 문자열로 만든 `href`를 쓰지 않는다(링크는 base62로 검증한 ID로만 만든다). 설명은 마크다운으로 렌더링하지 않는다. API 응답은 `Content-Type: application/json; charset=utf-8`와 `X-Content-Type-Options: nosniff`, 웹은 `Content-Security-Policy: default-src 'self'`.
8. **노드**: 서버에서 받은 ID와 해시는 base62 12자 정규식으로 검증한 뒤에 캐시 파일 이름으로 쓴다(경로 조작 방지). 받은 문서는 해시를 다시 계산해 대조한다(7절). 전개는 데이터만 해석하고 `eval` 같은 실행이 없다. 파싱·전개 예외는 잡아서 노드 오류로 보여 준다(Python `json`은 깊은 중첩에서 `RecursionError`).

## 10. 기술 스택과 구조

- TypeScript: Hono(API) + Vite/React(웹) + CodeMirror 6(편집기) + Kysely(SQL) + zod(스키마, `core`에서 공유)
- PostgreSQL(`pg_trgm`으로 태그 자동완성)
- Python: ComfyUI 노드
- npm workspaces 모노레포: `packages/core`, `apps/api`, `apps/web`, `deploy`. ComfyUI 노드는 별도 저장소 `joykst96/comfyui-wakaaka`(2026-11-04 분리, 공통 테스트 세트는 사본을 두고 출처 커밋을 적는다)
- 배포: 서버에서 docker compose(`app`, `postgres`). 터널은 compose에 두지 않고 서버 호스트의 systemd cloudflared(ingress 설정 파일)에 호스트 이름을 더해 쓴다(사용자 결정, 2026-11-04. 서버의 다른 서비스와 같은 방식). 아래 "운영 배포".

### 디자인 토큰

`joykst96/design-tokens`( 3층 토큰: 원시값 → 역할 → 컴포넌트)를 쓴다.

- **가져오는 방식:** 그 저장소 README 방식대로 폴더째 `apps/web/src/design-tokens/`에 복사하고, 받아 온 커밋을 `SOURCE.md`에 적는다(현재 `62e4232`). Vite에서 `import "./design-tokens/tokens.css"`. 형제 경로를 참조하지 않는 이유는 서버 빌드가 wakaaka 폴더만 받기 때문이다. 복사는 Phase 3에서 웹을 만들 때 한다.
- **앱 코드는 2층(역할) 토큰만 쓴다.** `scripts/check.mjs`로 앱 CSS를 검사해 날 값과 오타 토큰을 막는다(`npm run lint:css`).
- **wakaaka 전용 컴포넌트 토큰**(편집기 구문 색, 참조 칩, 오류 밑줄, 의존 트리 등)은 앱 쪽 `styles/components.css`에 3층 규칙대로 둔다. 색과 글꼴은 2층만 참조한다. 2층에 없는 기하 스케일(라운드, 테두리 두께, 크기)만 1층 스케일 토큰을 참조할 수 있다(토큰 저장소 3층 규칙 "1·2층 참조", README "스케일은 앱이 쓰라고 둔 것"). 1층 팔레트 색은 쓰지 않는다. 앱 CSS(`app.css`)와 CodeMirror 테마는 2층과 이 앱 3층 토큰만 쓴다. `apps/web/scripts/lint-css.mjs`가 `check.mjs`와 함께 이 층 규칙을 검사한다(Phase 3). 공용 저장소는 범용으로 유지한다.
- **새 색상이 필요한 경우**(예: Danbooru 태그 종류별 색)는 공용 저장소의 1·2층에 먼저 추가하고 다시 복사한다. 앱에서 hex를 만들지 않는다.
  - 태그 분류 색(Phase 5, 사용자 결정 2026-11-04): 공용 저장소 2층에 의미 없는 분류용 라벨 색 `--color-label-{blue,red,purple,green,orange}`(텍스트, 배경 위 4.5:1 이상)을 두고, 1층에는 보라·주황만 새로 넣는다(파랑·빨강·초록은 기존 1층 값). 앱 3층이 Danbooru 관례대로 잇는다: general 파랑, artist 빨강, copyright 보라, character 초록, meta 주황.
- CodeMirror 테마도 `var(--...)`로 토큰을 참조한다. 그래야 다크/라이트와 밀도를 그대로 따라간다.
- CodeMirror는 그림자 루트(ShadowRoot) 안에 띄운다. CodeMirror(style-mod)는 문서에는 `<style>` 태그로 스타일을 넣는데 CSP `default-src 'self'`가 그것을 막는다. 그림자 루트에서는 생성 스타일시트(adoptedStyleSheets)를 쓰고 이것은 CSP에 막히지 않는다(Phase 3 실측, `NOTES.md`). 그래서 편집기 모양은 CodeMirror 테마로만 정하고, 토큰은 사용자 정의 속성이 그림자 경계를 넘어 상속되는 것으로 받는다.
- 기본은 다크이고, OS가 라이트면 라이트로 바뀐다(토큰 기본 동작). 레이아웃은 `--layout-sidebar-width`를 쓰고, 900px 아래에서는 1단으로 바뀐다.
- `ui.css`(`.btn`, `.input`, `.chip`, `.panel`, `.popover`, `.dialog` 등)를 React 컴포넌트의 기반으로 쓴다. 컴포넌트에는 바깥 여백을 두지 않는다(토큰 레이아웃 규칙).

- 태그 CSV는 테스트와 같은 방식(해시 비교 후 전송, 컨테이너 안에서 가져오기)으로 운영 폴더의 `data/`에 넣는다.

  - 대상: 설명 맨 앞이 `[대분류 > 소분류]`이고, 그 표시를 뺀 본문이나 키워드에 한글이 있는 행(옛 `danbooru-tags.csv` 기준 71,142개). **NSFW를 거르지 않는다**(테스트 예시와 다름).
  - 헤더 없는 형식(mengod-hf, 2026-11-08 사용자 결정): 이 형식은 대괄호 분류를 태그마다 자유롭게 붙여 일반 태그의 `대분류 > 소분류` 쌍이 14,480개다(대부분 1~2개). 그래서 일반 태그는 **태그가 10개 이상인 쌍만** 와일드카드로 만들고(381개, 일반 31,763개 중 10,401개), 나머지 일반 태그는 기본 와일드카드에 넣지 않는다(자동완성에는 있다). 일반이 아닌 분류는 대괄호 표시와 상관없이 전부 넣는다. 운영에 이미 넣은 옛 CSV의 115개는 그대로 둔다(바꾸려면 사용자가 요청할 때 따로).
  - 소유자: 로그인하지 않는 전용 계정 `wakaaka`(비밀번호 무작위, 어디에도 남기지 않음). 사용자는 둘러보기에서 가져와 쓴다.
  - 묶는 방식: Danbooru 일반(general) 태그는 `[대분류 > 소분류]`마다 하나(이름 `대분류 > 소분류`). 아티스트·캐릭터·작품·메타 태그는 소분류를 보지 않고 분류 전체를 post_count 내림차순으로 5,000개씩 잘라 `아티스트 1`, `아티스트 2` …(문서 항목 상한이 5,000).
  - 항목은 태그 하나씩, 가중치는 모두 1, 개수 1~1. 텍스트는 자동완성과 같은 표기(`promptTag`, `escapeText`). 항목 ID는 태그 이름의 해시라 다시 만들어도 같다. 고정 분류(3절)는 대분류로 정한다.
- Cloudflare 설정(터널 ingress, 속도 제한, Cache Rule, 자동 삽입 스크립트)은 사용자가 한다. 목록과 값은 `NOTES.md` Phase 6.

### 폴더 (사용자 결정 2026-11-08)

내 와일드카드를 나누어 두는 정리용이다. 근거는 `NOTES.md` 2026-11-08 "사용자 폴더".

- **나만 본다.** 폴더는 로그인한 본인의 사이드바와 `/folders`에만 나온다. 둘러보기, 검색, 사용자별 목록, 와일드카드 조회, `/api/lookup`, `/api/w/*`에는 폴더 정보가 없다. 내 목록 `GET /api/wildcards`의 응답도 바뀌지 않는다(소속은 `GET /api/folders`로 따로 받는다).
- **한 단계**: 폴더 안에 폴더는 없다. **소속은 하나**: 와일드카드 하나는 폴더 하나에만 들어간다. 넣지 않은 것은 "폴더 없음"이다(`folder_id` NULL).
- 이름: 앞뒤 공백 없이 코드 포인트 1~64자. 문자열 검사(9절 "입력과 저장" 2항)에 더해 C0 제어문자 전부(탭·줄바꿈 포함)와 DEL을 받지 않는다(한 줄 이름). 와일드카드 이름의 금지 글자(`{ } $ \ | = :`)는 문법에 쓰이지 않으므로 막지 않는다. 같은 사용자 안에서 겹치지 않는다(대소문자 무시, `lower(name)` 유일 색인). 겹치면 409 `E_FOLDER_NAME_TAKEN`.
- 상한: 사용자당 폴더 100개(잠정, 넘으면 409 `E_FOLDER_LIMIT`). 폴더 안의 와일드카드 수는 제한하지 않는다. 한 번에 옮기는 수는 500개까지.
- 정렬(2026-11-09 바꿈): 폴더는 **사용자가 정한 순서**(`wc_folder.position`, 0008)다. 새 폴더는 만든 자리에 들어간다(아래 "우클릭 메뉴"). 0008은 기존 폴더에 그때 보이던 순서(`ORDER BY name, id`) 그대로 번호를 매긴다. 순서를 끌어서 바꾸는 기능은 없다(요청 범위 밖). 폴더 안은 지금 목록 순서(이름순) 그대로. 사이드바는 폴더를 위에, "폴더 없음"인 것을 그 아래에 놓는다. 폴더가 없으면 사이드바는 예전과 같다.
- 만들기·이름 바꾸기·지우기·옮기기는 모두 소유자를 잠근 트랜잭션에서 한다. 남의 폴더는 없는 것과 같은 404(`E_FOLDER_NOT_FOUND`, 만들기의 `after`도 같다), 남의 와일드카드를 옮기려 하면 403, 없거나 지운 와일드카드는 404이고 하나라도 걸리면 아무것도 옮기지 않는다.
- **폴더를 지우면** 안의 와일드카드는 지우지 않고 상위, 곧 "폴더 없음"으로 꺼낸다(한 단계라 상위는 "폴더 없음"뿐이다. FK `SET NULL`). 응답에 옮긴 개수를 준다. 화면은 지우기 전에 "안의 N개는 '폴더 없음'으로 옮겨집니다"로 확인을 받는다.
- **우클릭 메뉴**(사용자 결정 2026-11-09): 사이드바의 내 와일드카드 목록과 `/folders`의 폴더 칩 줄에서 브라우저 메뉴 대신 앱 메뉴를 띄운다. 키보드는 Shift+F10과 메뉴 키로 연다. Esc, 바깥 클릭, 스크롤로 닫힌다. 화살표로 고르고 Enter로 실행한다. 터치는 길게 눌렀다 떼면 열린다(아래 끌어 놓기와 같이 쓴다).
  - **새 폴더**: 우클릭한 곳 **바로 아래**에 생긴다(탐색기·목록 편집기의 "아래에 추가" 관례. 사용자가 위·아래 중 관용적인 쪽으로 정하라고 함). 폴더 위면 그 폴더 다음, 폴더 안의 와일드카드 위면 그 와일드카드가 든 폴더 다음(한 단계라 와일드카드 사이에는 폴더를 둘 수 없다), "폴더 없음"인 와일드카드·"전체"·"폴더 없음" 칩·빈 곳이면 폴더 목록 맨 끝이다. 그 자리에 이름 입력 칸이 바로 열리고 Enter(또는 이름을 적고 다른 곳을 누름)로 만든다. Esc나 빈 이름이면 만들지 않는다.
  - **폴더 지우기**: 폴더 위에서만 나온다. 위 "폴더를 지우면"대로 확인을 받는다. 와일드카드는 지우지 않는다.
- **끌어 놓기**(사용자 결정 2026-11-09): 사이드바와 `/folders`에서 와일드카드를 끌어 다른 폴더(사이드바는 폴더 머리나 그 안, `/folders`는 폴더 칩)나 "폴더 없음"에 놓으면 `POST /api/folders/move`로 옮긴다. 끄는 동안 놓을 수 있는 곳을 강조하고, 사이드바는 맨 아래에 "폴더 없음" 놓는 칸을 보인다. `/folders`에서 고른 것 중 하나를 끌면 고른 것이 모두 간다. 화면은 먼저 옮겨 보이고 실패하면 원래대로 되돌리고 알린다. 마우스는 조금 움직이면 끌기가 시작되고(그냥 누르면 링크 열기), 터치는 길게 누른 뒤 움직이면 시작된다(그냥 밀면 스크롤). 라이브러리 없이 포인터 이벤트로 만든다(HTML 끌어 놓기 API는 터치에서 안 된다). 키보드로는 기존대로 `/folders`에서 골라 옮긴다.
- **새 버전이 생기지 않는다.** 소속은 분류처럼 와일드카드에 붙는다. 내용 해시, 버전, `updatedAt`, 예시 출력, 둘러보기 순서가 바뀌지 않는다.
- 새로 만든 와일드카드와 **가져오기로 만든 복사본은 "폴더 없음"에** 들어간다. 가져오기에서 다시 쓴 기존 복사본은 있던 폴더에 그대로 있다.
- **와일드카드를 지우면** 목록과 폴더 개수에서 빠지지만 행의 `folder_id`는 남긴다. 관리자가 되살리면 원래 폴더로 돌아가고, 그 사이 폴더를 지웠으면 "폴더 없음"이다. 관리자 강제 삭제(9절 "관리")도 같다. **계정 삭제**는 폴더 행을 지운다.

    - 주석 행(아래)은 가중치 칸을 막고(입력 불가) 점선 테두리·비활성 바탕·취소선으로 칠한다. 비어 있으면 `#`를 자리표시자로 보인다. 값은 지우지 않으므로 맨 앞 `#`를 지우면 그 값으로 다시 쓸 수 있다(사용자 요청 2026-11-09). 읽기 전용 보기도 같은 모양이다.

  - **주석 항목**(3절): 두 보기 모두 `#`로 시작하는 행·줄을 주석 색으로 칠하고, 그 안에서는 구문 색·오류 밑줄·태그 표기 lint·자동완성을 하지 않는다. 저장할 때 이름 참조도 바꾸지 않는다(주석 안의 `${이름}`은 글자). 미리보기·내보내기에는 나오지 않는다.
  - 칩: 내 와일드카드는 채운 칩. 가져온 복사본은 같은 칩에 원작자 표시를 붙이고, 원본에 새 버전이 있으면 배지를 단다. 마우스를 올리면 원작자, 설명, 예시 출력 3개. 클릭하면 이동.
  - 자동완성:
    - `${`를 입력하면 와일드카드(내 것 → 즐겨찾기 → 둘러보기 검색)
    - 쉼표 뒤에서 글자를 치면 Danbooru 태그(분류 색, 포스트 수, 한국어 설명). 칸 맨 앞과 선택지 `{` `|` 뒤에서도 뜬다. 영문과 한국어로 찾는다(7절 "태그 자동완성"). Phase 5
    - **태그는 항상 공백으로 넣는다(밑줄 아님, 설정 없음).** 최근 모델은 모두 공백 표기를 쓴다.
    - **표기 변환은 자동완성이 넣을 때 프론트에서 한다.** 저장 데이터, 서버, 전개기는 텍스트 속 태그를 바꾸지 않는다. 사용자가 직접 친 글자는 그대로 둔다. 규칙은 `packages/core/src/tagtext.ts`(`promptTag`, `escapeText`) 한 곳에 있고 예시 생성기와 웹이 같이 쓴다. 넣을 때의 규칙(사용자 결정, 2026-11-04 확정):
      1. 밑줄은 모두 공백으로. 단 이름에 영숫자가 2글자 이상 이어진 곳이 없으면(이모티콘 `^_^`·`>_<`·`o_o`·`<|>_<|>` 등 general 19개, `m_k` 같은 작가·작품 15개) 그대로 둔다.
      2. 괄호는 ComfyUI 가중치로 읽히지 않게 `\(` `\)`로. ComfyUI의 이스케이프는 이 둘뿐이라 `\m/` 같은 다른 백슬래시는 그대로 둔다.
      3. 와카아카 특수문자를 이스케이프한다(`escapeText`). 넣는 자리가 선택지 안이면 `|`도.
      4. 친 조각만 바꾸고 뒤에 쉼표를 붙이지 않는다.
    - **표기 lint**(Phase 5): 쉼표·선택지로 나눈 조각이 태그 DB의 태그인데 밑줄로 썼거나(`long_hair`) 괄호를 이스케이프하지 않았으면(`hatsune miku (cosplay)`, ComfyUI가 가중치 1.1로 읽는다) 정보 밑줄과 "고치기"(위 규칙으로 바꾼 표기)를 보여 준다. 자동으로 바꾸지 않는다. 폐기 태그 lint는 나중이다(13절).
  - 이름 참조를 ID로 바꾸기(저장할 때): 내 와일드카드에 같은 이름(대소문자 무시)이 있으면 그것으로 바꾼다. 내 것 안에서는 이름이 유일해서 겹치지 않는다. 내 것에 없으면 저장 전에 후보 창(즐겨찾기 → 둘러보기 검색)을 띄워 고르게 하고, 남의 것을 고르면 가져오기 확인을 거친다. 몰래 가져오지 않는다(사용자 결정, 2026-11-03).
  - Ctrl+S 저장. 저장 안 한 내용은 브라우저에 임시 보관하고, 페이지를 벗어나면 경고한다.
  - 오류 밑줄: 닫히지 않은 `{`, 없는 참조, 상한 초과.
- **오른쪽 패널**
  - 미리보기: seed 입력과 주사위. seed를 하나씩 늘린 결과 5개. 결과의 어느 부분에 마우스를 올리면 그 부분이 어느 와일드카드에서 왔는지 강조한다(전개기가 출처 범위를 같이 돌려준다).
  - 사용하는 것: 하위 트리. 같은 와일드카드가 두 번째로 나오면 "↑ 위에 있음"으로 처리한다.
  - 사용되는 곳: 이 와일드카드를 참조하는 내 와일드카드.
  - 내보내기: 드롭다운(Impact Pack[기본], 와카아카)과 복사 버튼. 지금 보이는 내용(저장 안 한 것 포함)을 클립보드로 복사한다. Impact Pack은 아래 변환 결과 한 줄, 와카아카는 텍스트 보기 형식(`3* red hair`, 한 줄에 항목 하나). 두 형식 모두 주석 항목(3절)은 빼고 내보낸다(텍스트 보기 칸 자체에는 주석이 남는다). 변환 경고가 있으면 복사하면서 보여 준다(사용자 결정 2026-11-03: 경고 후 그대로 복사). 복사 결과는 토스트로 알리고(경고가 있으면 경고 토스트 "변환 경고 N개는 내보내기 패널에 있습니다"), 경고 목록은 패널에 남긴다.
- 900px 미만: 사이드바는 서랍 메뉴로, 오른쪽 패널은 편집기 아래로.

### 알림: 토스트와 제자리 오류 (사용자 결정 2026-11-09)

- 동작의 결과(복사됨, 저장됨, 실패)는 **오른쪽 아래 토스트**로 알린다(`components/Toast.tsx`, 규칙은 `lib/toasts.ts`). 어느 화면에서든 `useToast()`로 띄운다(폴더 사이드바의 오류 줄도 나중에 옮길 수 있게 범용).
  - 3초 뒤 사라진다. 마우스를 올리거나 포커스가 안에 있으면 멈추고, 떠나면 3초를 다시 센다. ×로 닫는다.
  - 여러 개는 아래로 쌓인다(새 것이 맨 아래, 최대 4개, 넘치면 오래된 것부터). 같은 종류·같은 글이 다시 오면 겹쳐 쌓지 않고 맨 아래로 옮겨 시간을 다시 센다.
  - 종류: 정보·성공·경고·오류(왼쪽 띠 색). 화면 읽기 프로그램은 오류(동작 실패)만 `role="alert"`, 나머지는 `role="status"`. 두 읽기 영역은 늘 DOM에 두고 그 안에 토스트를 넣는다.
  - 모바일 폭에서도 화면 안쪽 여백(`--toast-offset`) 안에 있고 가로 스크롤을 만들지 않는다. 움직임 줄이기 설정이면 나타나는 효과를 끈다.
- 토스트로 옮긴 것: ID 복사(성공·클립보드 막힘), 내보내기 복사(성공, 실패: 불러오는 중·변환 불가·클립보드 막힘·이름 참조 미해결, 변환 경고 개수), 저장(저장했습니다, 바뀐 내용 없음, 저장 취소, 저장 경고: 깊이·묶음 크기·가중치 합 0), 텍스트 보기로 못 바꿈(줄바꿈 든 항목), 삭제 실패(쓰는 곳 있음), 남의 것 보기의 "로그인해야 합니다"·좋아요·즐겨찾기 실패, 설정의 비밀번호 바꿈.
- 제자리에 남긴 것(고칠 때까지 보여야 하는 것): 저장 오류(문법·이름·순환 등, 그 항목을 빨갛게), 텍스트 보기 가중치 범위 오류, 복구 제안 띠(복구/버리기), 옛 버전 보기 띠, 로그인·가입·비밀번호 입력 오류, seed 입력 오류, 다이얼로그 오류, 폴더 화면 오류, 페이지 불러오기 실패.

### 남의 와일드카드와 가져오기

- 읽기 전용 보기는 같은 배치에서 편집만 잠근다. 버튼: 좋아요(개수), 즐겨찾기, 가져오기, ID 복사. 버전 이력을 볼 수 있다. 설명은 테두리 없는 글자로 보인다.
- 가져오기(버튼, 즐겨찾기에서 끌어다 넣기, `${` 자동완성에서 남의 것 고르기)는 "내 와일드카드 N개로 복사됩니다(이미 있는 복사본 M개는 다시 씀)" 확인 창을 띄운 뒤 실행한다.
- 사이드바의 내 와일드카드 목록에는 복사본도 나온다. 원작자 표시를 붙이고, "가져온 것 숨기기" 체크박스를 둔다. 기본은 꺼짐(다 보임)이고 켠 상태는 그 브라우저에 기억한다(사용자 결정, 2026-11-03).

### Impact Pack 내보내기 (2026-11-03)

Impact Pack 와일드카드 노드(`ImpactWildcardProcessor`·`ImpactWildcardEncode`)의 텍스트 칸에 붙여 넣어 쓰는 프롬프트 한 줄을 만든다. 하위 와일드카드는 파일(`__이름__`) 없이 모두 그 자리에 펼쳐 넣는다. 변환기는 `packages/core`에 두고 API(`/api/w/{id}/export`)와 웹(저장 안 한 내용)이 같이 쓴다(사용자 결정).

| 와카아카 | Impact Pack |
|---|---|
| 와일드카드(개수 1~1) | `{w1::항목1\|w2::항목2\|…}` |
| 개수 a~b, 구분자 s | `{a-b$$s$$w1::항목1\|…}` |
| 항목 가중치, 펼친 항목 | 각 보기 앞 `w::`. 가중치 0인 항목과 주석 항목은 뺀다. 펼친 참조는 대상 항목들을 같은 목록에 넣는다 |
| 참조 `${w:X}`, ref 항목 | X를 같은 규칙으로 바꾼 `{…}`를 그 자리에(다이아몬드·반복은 나올 때마다 다시 펼친다) |
| 선택지 `{3*a\|b}` | `{3::a\|1::b}`(가중치 0인 보기는 뺀다) |

- 모든 보기에 가중치를 적는다(`1::`도). Impact는 보기 맨 앞의 `숫자::` 하나만 가중치로 떼므로, 보기가 NAI 강조 `1.2::tag::`로 시작해도 그대로 남는다. 또 Impact는 **가중치 합이 1 이하이면 보기를 전부 출력**하므로 가중치 0인 보기를 남기지 않는다(정수 가중치라 보기가 둘 이상이면 합이 2 이상).
- Impact는 `|`를 이스케이프할 수 없다. 글자 `|`(태그 `:|` `|_|` `\||/` 등 6개), 글자 `{` `}`(Impact에서 `\{`로 남는다), `$$`, `__이름__` 모양, 구분자 안의 `|` `$$` `{` `}`는 경고하고 그대로 둔다. 줄바꿈은 공백으로 바꾸고 경고한다(Impact는 `#`로 시작하는 줄을 주석으로 지운다).
- 난수가 달라서 같은 seed여도 와카아카와 결과가 다르다. 뽑힐 확률만 같게 맞춘다. 와카아카의 최종 쉼표 정리(SPEC 4.4)는 Impact가 하지 않는다. 결과가 매우 크면(100KB 넘음) 경고한다.

### 둘러보기 카드

이름, 소유자, 설명, 분류, 좋아요 수, 예시 출력 한 줄. 예시 출력은 저장할 때 고정 seed로 한 번 계산해 둔다. 목록을 볼 때마다 전개하지 않는다. 가져온 복사본은 고치지 않았으면 둘러보기·검색에 나오지 않는다(사용자 결정, 2026-11-03). 가져오기 한 번에 복사본이 수십 개 생겨 최신순을 덮기 때문이다. 복사본은 사용자 페이지와 직접 링크로 볼 수 있다.
- 고친 복사본은 나온다(사용자 결정, 2026-11-04). 고쳤다 = 최신 버전 해시가 가져온 직후의 1번 버전 해시와 다르다. 이름·설명·항목을 바꾸면 해당하고, 분류만 바꾸거나 가져온 내용으로 되돌리면 해당하지 않는다. 카드에 "가져옴(원작자)"를 붙인다. 같이 가져온 하위 복사본은 각자 고쳤을 때만 나온다.
- 원본 새 버전으로 갱신하기(2절 3항)를 만들 때는 갱신이 만든 버전을 "고침"으로 치지 않도록 이 기준을 다시 정한다.

- CI는 당분간 두지 않는다. 커밋 전에 로컬에서 `npm test`를 돌린다.

## 13. 범위: 첫 버전과 나중

| 첫 버전 (MVP) | 나중에 |
|---|---|
| 계정, 내 와일드카드 저장과 버전 | 태그 재정렬(분류별 우선순위, 처음엔 고정 프리셋 하나), 중복 제거 |
| 인라인 문법, 참조, 가져오기(의존성 복사) | 매개변수와 변수 |
| 편집기: 자동완성, seed 미리보기, 의존 트리 | 원본 업데이트 알림과 diff, 저장 전 영향 분석 경고 화면 |
| 즐겨찾기, 둘러보기(인기순·최신순, 검색, 분류), 좋아요 | 폐기 태그 lint |
| `bundle`, `resolve` API | 워크플로에 묶음 내장 옵션 |
| 노드: 서버 모드 → 로컬 모드 | 출력 순서 필드 `select.order`(뽑힌 순서 대신 문서 순서. 품질 태그처럼 순서를 지킬 목록용) |

- **나중 기능을 위해 처음부터 지킬 것:** 항목 ID와 하위 seed 경로 규칙은 첫 버전부터 넣는다. 나중 기능을 붙여도 기존 결과가 바뀌지 않게 하기 위해서다. 매개변수 문법 자리(`${이름 키=값}`)와 `select.order` 필드 이름도 예약해 둔다. `select.order`의 기본값은 지금 동작(뽑힌 순서)이라 나중에 붙여도 기존 결과가 바뀌지 않는다.
- **태그 재정렬 메모:**
  - 괄호 바깥의 쉼표로 조각내고, 가중치를 벗기고, 이름을 정규화하고, 별칭을 풀어서 태그 DB에서 분류를 찾는다.
  - 같은 분류 안에서는 원래 순서를 유지한다(안정 정렬). 미분류 조각은 별도 순위를 준다. `<lora:>`와 `BREAK`는 움직이지 않는다.
  - 기본은 off. 응답과 lock에 분류 데이터 버전을 넣는다.
  - 기본 타입(캐릭터·작품·작가·일반)은 모든 태그에 있다. 세부 분류는 예전 체계로 시작하고, TAXONOMY 2.0이 완성되면 바꾼다.
- **조건부 뽑기는 기능으로 두지 않는다.** 조합으로 표현한다(3절).
