# 와카아카 명세 (문법, 전개, 난수)

갱신: 2026-11-03. 설계는 `DESIGN.md`, 결정의 근거는 작업 메모 `NOTES.md`(공개 저장소에는 넣지 않음)에 있다.
TS 전개기와 Python 전개기는 이 문서와 `packages/core/conformance`의 공통 테스트 세트를 기준으로 만든다.
명세를 바꿀 때는 테스트 세트를 먼저 고친다.

## 1. 범위와 용어

- **항목 텍스트**: 문서 `items[].text`의 문자열. 인라인 문법은 여기에만 적용한다. `sep`, `name`, `description`은 글자 그대로다.
- **저장 형태**: DB와 묶음에 들어가는 문서. 참조는 내 와일드카드 `${w:ID}`뿐이다(`DESIGN.md` 2절). 전개기는 저장 형태만 받는다.
- **편집 형태**: 편집기에서 사용자가 쓰는 문서. 참조를 `${이름}`으로 쓸 수 있고, 저장할 때 저장 형태로 바꾼다.
- 문자는 유니코드 코드 포인트 단위로 본다. 특수문자는 모두 ASCII다.
- **공백**: 이 명세에서 "공백"은 U+0020, U+0009, U+000A, U+000D 네 글자만 뜻한다. 언어마다 `trim`/`strip`이 지우는 글자가 달라서 직접 정한다.

## 2. 인라인 문법

### 2.1 EBNF

ISO EBNF(`{ }` 0번 이상 반복, `[ ]` 생략 가능, `-` 제외)로 쓴다. 특수문자는 큰따옴표 안의 글자다.

```ebnf
text          = { segment } ;
segment       = escape | ref | choice | literal ;

(* 즉석 선택지. 보기는 하나 이상이고, 보기는 비어 있을 수 있다. *)
choice        = "{" , alt , { "|" , alt } , "}" ;
alt           = [ weight ] , { alt_segment } ;
weight        = digit , { digit } , "*" ;          (* 보기 가중치. 2.2절 0 *)
alt_segment   = alt_escape | ref | choice | alt_literal ;

(* 참조. 본문은 처음 나오는 "}"까지다. 본문 해석은 2.3절. *)
ref           = "$" , "{" , ref_body , "}" ;
ref_body      = { any_char - "}" } ;

escape        = "\" , esc_target ;
alt_escape    = "\" , ( esc_target | "|" ) ;
esc_target    = "{" | "}" | "$" | "\" ;

(* 아래 literal 규칙의 예외는 EBNF로 쓰기 어려워 2.2절의 우선순위로 정한다. *)
literal       = any_char - ( "{" | "}" ) ;
alt_literal   = any_char - ( "{" | "}" | "|" ) ;

(* 저장 형태의 참조 본문 *)
stored_body   = "w:" , id12 ;
id12          = b62 , b62 , b62 , b62 , b62 , b62 , b62 , b62 , b62 , b62 , b62 , b62 ;
b62           = "0" | ... | "9" | "A" | ... | "Z" | "a" | ... | "z" ;
```

### 2.2 읽는 순서

파서는 왼쪽에서 오른쪽으로 한 글자씩 읽고, 각 위치에서 다음 순서로 처음 맞는 규칙을 쓴다.
"선택지 안"은 닫히지 않은 `{`가 하나 이상 있는 상태다.

0. **보기 시작**(규칙 3으로 선택지를 열거나 규칙 4로 보기를 나눈 바로 뒤): 이어지는 글자가 숫자와 점(`0-9` `.`) 하나 이상이고 바로 뒤가 `*`이면 보기 가중치로 읽고 `*`까지 넘긴다. 숫자만이고 값이 0~1,000,000이면 그 값이 가중치다(앞의 0은 무시). 점이 있거나 1,000,000을 넘으면 `E_CHOICE_WEIGHT`. 그렇지 않으면 아무것도 읽지 않고 그 자리에서 규칙 1~6을 쓴다. 보기 하나에서 가중치는 맨 앞에서 한 번만 읽는다.

1. `\` 다음 글자가 `{` `}` `$` `\`이거나, 선택지 안에서 `|`이면: 그 다음 글자를 글자 그대로 넣고 두 글자를 넘긴다.
2. `$` 다음 글자가 `{`이면: 참조를 시작한다. 그 뒤에서 처음 나오는 `}`까지가 본문이다. `}`가 없으면 `E_UNCLOSED_REF`.
3. `{`: 선택지를 시작한다. 이미 64겹이 열려 있으면 `E_NESTING`.
4. 선택지 안의 `|`: 보기를 나눈다.
5. `}`: 선택지 안이면 선택지를 닫는다. 바깥이면 `E_UNMATCHED_CLOSE`.
6. 그 밖의 글자(위에 해당하지 않는 `\`, `$`, 선택지 바깥의 `|` 포함): 글자 그대로 넣는다.

끝까지 읽었는데 선택지가 열려 있으면 `E_UNCLOSED_CHOICE`. 규칙 5로 선택지를 닫을 때 모든 보기의 가중치가 0이면 `E_CHOICE_WEIGHT`(위치는 여는 `{`).

가중치를 적지 않은 보기의 가중치는 1이다. `{ 3*a}`처럼 앞에 공백이 있으면 가중치가 아니라 글자다. 글자 `3*x`로 시작하는 보기는 `{1*3*x}`로 쓴다(가중치는 한 번만 읽으므로 뒤의 `3*`는 글자). 선택지 바깥의 `3*`는 언제나 글자다(항목 가중치는 `w` 필드).

### 2.3 참조 본문 해석

본문(`${`와 `}` 사이)을 다음 순서로 판정한다.

| 순서 | 조건 | 결과 |
|---|---|---|
| 1 | 비어 있거나 공백뿐 | `E_REF_EMPTY` |
| 2 | `=`가 들어 있음 | `E_REF_RESERVED` (매개변수 `${이름 키=값}`, 변수 `${=변수}` 자리) |
| 3 | `{` `$` `\` `\|` 중 하나가 들어 있음 | `E_REF_INVALID` |
| 4 | `h:`로 시작함 | `E_REF_RESERVED` (예전 해시 참조 자리. 2026-11-03에 없애고 접두사만 예약했다) |
| 5 | `w:` + base62 12자와 정확히 같음 | 내 와일드카드 참조 |
| 6 | `:`가 들어 있음 | `E_REF_INVALID` (이름에는 `:`를 쓸 수 없으므로 잘못 쓴 저장 형태다) |
| 7 | 그 밖 | 이름 참조. 앞뒤 공백을 지운 것이 이름이다. 저장 형태에서는 `E_REF_NAME` |

- 저장 형태의 본문에는 공백이 붙을 수 없다. `${ w:abc }`는 6번에 걸려 `E_REF_INVALID`다.
- 4번은 편집 형태에서도 같다. 대문자 `H:`는 예약이 아니라 6번(`E_REF_INVALID`)이다.
- 이름 참조를 ID로 바꾸는 규칙(대소문자 무시, 내 것 → 즐겨찾기 순 등)은 편집기·API 쪽 일이다. 전개기는 이름 참조를 받지 않는다.

### 2.4 구문 트리 (공통 표기)

공통 테스트 세트는 파서 결과를 아래 JSON으로 비교한다. 구현 내부 표현은 자유다.

| 노드 | JSON |
|---|---|
| 글자 | 문자열. 이웃한 글자는 하나로 합친다. 빈 문자열은 만들지 않는다. |
| 참조 | `{"ref": "w", "id": "<12자>"}`, 편집 형태에서만 `{"ref": "name", "name": "<이름>"}` |
| 선택지 | `{"choice": [<보기>, ...]}`. 보기는 노드 배열이다. 빈 보기는 `[]`. 보기 중 하나라도 가중치를 적었으면 `"w": [<가중치>, ...]`를 더한다(적지 않은 보기는 1). 하나도 적지 않았으면 `w`가 없다. |

텍스트 전체도 노드 배열이다. 빈 텍스트는 `[]`.

**노드 번호**: 텍스트 안의 참조와 선택지에 전위 순회(노드 자신 → 첫 보기의 노드들 → 둘째 보기 …) 순서로 0부터 번호를 매긴다.
뽑히지 않은 보기 안의 노드에도 번호를 매긴다. 번호는 텍스트만으로 정해지고, 하위 seed 경로의 "참조 위치"로 쓴다(4절).

### 2.5 경계 사례

아래는 원문 그대로다(마크다운 이스케이프 없음). `[a]`는 보기, `"…"`는 글자, `<w:…>`는 참조다.

```text
입력                 결과                                 비고
{a|b}                {[a] [b]}
{a|}  {|a}           빈 보기가 있는 선택지                빈 보기도 같은 확률로 뽑힌다
{}                   {[]} → 항상 ""
{|}                  {[] []}
{{masterpiece}}      {[{[masterpiece]}]} → "masterpiece"  NovelAI 강조를 붙여 넣은 경우
{a|{b|c}}            중첩 선택지                          a 1/2, b·c 각 1/4
{a|${w:…}}           선택지 안의 참조                     참조는 뽑힐 때만 전개된다
a|b                  "a|b"                                선택지 바깥의 |는 글자다
\|                   "\|" (두 글자)                       바깥에서 \|는 이스케이프가 아니다
\||/                 "\||/"                               태그가 바깥에서는 그대로 남는다
a\\|b                "a\|b"                               \\가 \, 이어지는 |는 바깥이라 글자
{\||/}               {["|"] ["/"]}                        안에서는 \|가 이스케이프, 다음 |는 구분
{\\\|\|/}            {["\||/"]}                           선택지 안에 태그 \||/를 쓰는 방법
\(  \m/  \o/         글자 그대로                          대상이 아닌 백슬래시는 남긴다
abc\                 "abc\"                               끝의 백슬래시
\\{a}                "\" + {[a]}                          \\가 먼저 짝지어진다
\{a\}                "{a}"
$  $5  $ {a}         글자 그대로 (마지막은 "$ " + {[a]})   $는 바로 뒤가 {일 때만 특수문자
$${w:…}              "$" + <w:…>
\${a}                "$" + {[a]}                          \$는 참조 시작만 막는다. {는 여전히 선택지
$\{a\}               "${a}"                               글자 ${…}를 쓰는 방법
{a                   E_UNCLOSED_CHOICE                    위치는 닫히지 않은 가장 안쪽 {
a}                   E_UNMATCHED_CLOSE
${w:abc              E_UNCLOSED_REF
${}  ${  }           E_REF_EMPTY
${a{b}c}             E_REF_INVALID                        본문이 a{b가 된다
${w:short}           E_REF_INVALID                        12자가 아니다
${ w:abcdefghijkl }  E_REF_INVALID                        저장 형태에는 공백을 붙일 수 없다
${hair color}        편집 형태: 이름 "hair color"
                     저장 형태: E_REF_NAME
${이름 색=red}  ${=x}  E_REF_RESERVED                       예약
${h:…}               E_REF_RESERVED                       해시 참조는 없앴고 접두사만 예약
{ 65겹               E_NESTING                            64겹까지 허용
{3*silver|platinum}  {[silver] [platinum]} w=[3,1]          보기 가중치. silver 3/4
{3*a|1*b}            {[a] [b]} w=[3,1]                   적지 않은 것과 1을 적은 것은 같다
{0*a|b}              {[a] [b]} w=[0,1]                   0은 뽑히지 않는다
{2*{a|b}|c}          {[{[a] [b]}] [c]} w=[2,1]           가중치 뒤에 선택지
{1*3*x}              {[3*x]} w=[1]                       글자 3*x로 시작하는 보기
{ 3*a}  {*a}  {3 *a}  글자 그대로 (가중치 아님)              맨 앞에 바로 숫자와 *가 와야 한다
{2girls|solo}        글자 그대로                          숫자 뒤가 *가 아니면 가중치가 아니다
3*a  {a|b}3*c        글자 그대로                          선택지 바깥과 보기 중간은 글자
{1.5*a|b}            E_CHOICE_WEIGHT                      정수만
{1000001*a}          E_CHOICE_WEIGHT                      0~1,000,000
{0*a|0*b}            E_CHOICE_WEIGHT                      모든 보기가 0
```

### 2.6 문법 오류 코드

| 코드 | 뜻 |
|---|---|
| `E_UNCLOSED_CHOICE` | 닫히지 않은 `{` |
| `E_UNMATCHED_CLOSE` | 짝이 없는 `}` |
| `E_UNCLOSED_REF` | 닫히지 않은 `${` |
| `E_REF_EMPTY` | 빈 참조 |
| `E_REF_INVALID` | 참조 본문에 쓸 수 없는 글자, 잘못된 저장 형태 |
| `E_REF_RESERVED` | 예약된 매개변수·변수 문법, `h:` 접두사 |
| `E_REF_NAME` | 저장 형태에 이름 참조가 남아 있음 |
| `E_NESTING` | 선택지가 64겹을 넘음 |
| `E_CHOICE_WEIGHT` | 보기 가중치가 정수가 아니거나 0~1,000,000 밖, 또는 모든 보기의 가중치가 0 |

- 오류가 여러 개면 처음 만난 것 하나만 낸다. 공통 테스트 세트는 오류 코드만 비교하고 위치는 비교하지 않는다.
- 오류 위치는 편집기 밑줄용이다. TS는 UTF-16 오프셋을 쓴다.
- 저장할 때 문법 오류가 있으면 저장을 거부한다(`DESIGN.md` 5절 1단계). 저장된 문서는 항상 파싱된다.

## 3. 문서와 묶음 (전개에 쓰는 부분)

### 3.1 문서

| 필드 | 형식 | 기본값 | 규칙 |
|---|---|---|---|
| `schema` | 정수 | 필수 | `1` |
| `select.count` | `[min, max]` 정수 | `[1, 1]` | `0 ≤ min ≤ max ≤ 5000` |
| `select.sep` | 문자열 | `", "` | 글자 그대로. 인라인 문법을 적용하지 않는다 |
| `items` | 배열 | 필수 | 5000개 이하. 비어 있어도 전개는 된다(빈 문자열) |
| `items[].id` | 문자열 | 필수 | base62 1~16자. 문서 안에서 유일 |
| `items[].text` | 문자열 | | `text`와 `ref` 중 정확히 하나 |
| `items[].ref` | `{"wildcard": ID}` | | 키는 `wildcard` 하나뿐, 값은 base62 12자. 예전 `{"hash": …}`는 `E_DOC` |
| `items[].w` | 정수 | `1` | `0 ≤ w ≤ 1000000`. `spread: true`인 항목에는 쓸 수 없다 |
| `items[].spread` | 불리언 | `false` | `ref` 항목에만 쓸 수 있다 |

- 그 밖의 필드(`name`, `description` 등)는 전개에 쓰지 않는다. 전개기는 문서·`select`·항목 단계의 모르는 필드를 무시한다(전개 사례 38). `ref` 객체만 예외로, 키가 `wildcard` 하나가 아니면 `E_DOC`다. 저장은 모르는 필드를 거부한다(3.3절).
- 예약: `select.order`(출력 순서, 나중 기능). 지금은 다른 필드처럼 무시한다. 붙일 때 기본값은 지금 동작(뽑힌 순서)이다.
- 규칙을 어기면 `E_DOC`. 정수 자리에 `3.0`처럼 소수부가 0인 수가 오면 정수로 본다(JS는 둘을 구분하지 못하고, JCS도 같은 값으로 직렬화한다).
- "쓸 수 없다"는 키가 있는 것을 뜻한다. text 항목에 `spread`가 있으면 값이 `false`여도 `E_DOC`(전개 사례 39), `spread: true` 항목에 `w`가 있으면 값이 `1`이어도 `E_DOC`다.
- 가중치를 정수로 정한 이유: 뽑기를 정수 산술만으로 정의하면 두 언어가 같은 결과를 내는지 따질 부동소수점 문제가 없다. 상대값이므로 정수로도 어떤 비율이든 표현할 수 있다(0.3:0.7 → 3:7).
- 가중치 합이 0인 문서는 저장할 때 거부한다(`DESIGN.md` 4절). 전개기는 그런 문서를 만나면 빈 문자열을 낸다(편집 중 미리보기용).

### 3.2 묶음

`DESIGN.md` 7절의 묶음 형식(`format`, `root`, `lock`, `docs`)을 그대로 받는다.

- `${w:ID}`와 `{"wildcard": ID}`는 `lock[ID]`의 해시로 `docs`에서 찾는다. 문서 안 어디에 있든 같은 `lock`을 쓴다. 루트만 `root`의 해시로 직접 찾는다.
- 전개기는 `docs`의 키와 내용이 맞는지(해시) 검증하지 않는다. 해시 검증(7절)은 묶음을 받을 때 따로 한다. 공통 테스트 세트는 읽기 쉬운 가짜 해시(`hairColor001` 같은 base62 12자)를 쓴다.
- `lock`의 값이 문자열이 아니거나 `docs`에 없으면 그 참조는 `E_UNRESOLVED`다.

### 3.3 저장 형식 (API)

API가 저장하는 문서와 노드가 받는 묶음에는 3.1절보다 엄격한 규칙을 쓴다(`DESIGN.md` 9절 "입력과 저장"). TS는 `packages/core`의 zod 스키마(`docSchema`, `bundleSchema`)가 이 규칙이다. 전개기는 이 규칙을 검사하지 않는다(3.1절만 본다).

- 필드는 3.1절 표의 것과 `name`, `description`만 쓸 수 있다. 그 밖의 필드는 어느 단계에서든 거부한다. 예약된 `select.order`도 지금은 거부한다(구현 전에 저장된 값이 나중에 결과를 바꾸지 않게).
- `name`(선택): 공백(1절)뿐이면 안 되고, `{ } $ \ | = :`를 쓸 수 없다(잠정). `description`(선택): 문자열.
- 모든 문자열: 올바른 유니코드(짝 없는 서로게이트 없음), U+0000 없음, 탭·줄바꿈·CR을 뺀 C0 제어문자(U+0001~U+001F) 없음(잠정).
- 키 `__proto__`는 어디에도 쓸 수 없다. 묶음의 `root`, `lock`의 키와 값, `docs`의 키는 base62 12자다.
- 기본값을 채우지 않는다. 검증을 통과한 문서는 받은 필드 그대로 정규화(7절)한다. 그래서 `select`를 생략한 문서와 기본값을 적은 문서는 해시가 다르다.
- 가중치 합이 0인 문서의 저장 거부(`DESIGN.md` 4절)는 `spread` 대상까지 봐야 하므로 이 스키마가 아니라 API의 참조 검증 단계에서 한다. spread를 펼친 후보(4.2절 `pool`)가 하나 이상이고 그 `w` 합이 0이면 거부한다. 후보가 없으면 받는다.
- 이름의 필수 여부와 길이(코드 포인트 1~64자, 앞뒤 공백 거부)도 API가 본다. 묶음 안 문서는 이름이 없어도 된다.

## 4. 전개

입력: 묶음, seed(부호 없는 64비트 정수), 상한(5절). 출력: 문자열, 또는 오류 코드 하나.

### 4.1 사전 검사

전개를 시작하기 전에 seed와 무관하게 다음을 검사한다. 그래서 오류는 seed에 따라 나왔다 안 나왔다 하지 않는다(`E_BUDGET` 제외).

1. `format`이 `1`이 아니면 `E_FORMAT`. 묶음이 객체가 아니거나 `root`가 문자열이 아니거나 `lock`·`docs`가 객체가 아니어도 `E_FORMAT`(전개 사례 40). seed가 `0 ≤ seed < 2^64`가 아니면 `E_SEED`.
2. `root`가 `docs`에 없으면 `E_UNRESOLVED`.
3. 루트에서 닿는 모든 문서에 대해: 스키마(`E_DOC`), 모든 `text` 항목의 문법(2.6절 코드), 모든 참조의 해결(`E_UNRESOLVED`)을 검사한다.
   뽑히지 않을 항목도 검사한다. 루트에서 닿지 않는 문서는 보지 않는다.
4. 참조 그래프(인라인 참조, `ref` 항목, `spread` 모두 간선)에 순환이 있으면 `E_CYCLE`. 정상적인 묶음에는 생길 수 없지만 `lock`이 잘못되면 생긴다.
5. 루트에서 시작하는 가장 긴 간선 경로가 `maxDepth`보다 길면 `E_DEPTH`. 루트만 있으면 0, 루트가 다른 문서를 참조하면 1이다.

여러 오류가 있을 때 어느 코드를 낼지는 정하지 않는다. 공통 테스트 세트는 오류가 하나뿐인 입력만 쓴다.

### 4.2 절차

seed 문맥 `c`는 64비트 정수다. 루트 문서의 문맥은 입력 seed 그대로다. `derive`와 `SplitMix64`, `bounded`는 6절에 있다.

```text
expand(묶음, seed) = cleanup(expand_doc(루트 문서, seed))      # cleanup은 4.4절. 맨 끝에 한 번만

expand_doc(D, c):
    예산을 1 쓴다                                   # 5절 maxExpansions
    entries ← pool(D, [])
    rng ← SplitMix64(derive(c, "select"))
    k ← min + bounded(rng, max − min + 1)           # min==max여도 한 번 뽑는다
    cands ← w > 0인 entries를 key 순으로 정렬
    k ← min(k, len(cands))
    picks ← cands에서 가중치 비복원 추출 k번 (6.4절, 같은 rng 계속 사용)
    parts ← []
    picks의 각 e에 대해 (뽑힌 순서대로):
        t ← c에서 시작해 e.key의 각 id마다 t ← derive(t, "item:" + id)
        s ← expand_item(e.item, t)
        s가 빈 문자열이 아니면 parts에 붙인다
    return parts를 sep으로 이은 것

pool(D, prefix):                                    # spread를 펼친 후보 목록
    D.items의 각 항목 it에 대해 (문서 순서):
        it가 spread면: 예산을 1 쓴다. pool(대상 문서, prefix + [it.id])를 이어 붙인다
        아니면: (item = it, key = prefix + [it.id], w = it.w)를 붙인다

expand_item(it, t):
    it가 ref 항목이면: return expand_doc(대상 문서, derive(t, "pos:0"))
    ast ← parse(it.text), 노드에 2.4절의 번호를 매긴다
    return render(ast, t)

render(노드 목록, t): 각 노드를 이어 붙인 문자열
    글자 → 그대로
    번호 p인 참조 → expand_doc(대상 문서, derive(t, "pos:" + p))
    번호 p인 선택지 → rng ← SplitMix64(derive(t, "pos:" + p))
                      a ← 보기 가중치로 6.4절 추출 1번 (보기 순서대로, 가중치 0인 보기도 자리는 그대로)
                      render(보기[a], t)
```

- **key 정렬**: key는 id 목록이다. 앞에서부터 한 id씩 비교하고(ASCII 순, id는 base62라 언어 차이가 없다), 앞부분이 같으면 짧은 쪽이 먼저다. 문서 안에서 id가 유일하므로 key도 유일하다.
- **출력 순서는 뽑힌 순서**다. 문서의 항목 순서는 결과에 아무 영향이 없다(정렬 때문). 편집기에서 항목을 끌어 옮겨도 같은 seed의 결과가 그대로다.
- **빈 결과는 잇지 않는다**: 뽑힌 항목의 결과가 빈 문자열이면 구분자도 붙이지 않는다. 빈 항목을 "없음" 보기로 쓸 수 있다. 쉼표가 아닌 구분자(`" | "` 등)에도 통한다. 텍스트 안에서 참조가 빈 문자열이 되어 생긴 `a, , b`는 4.4절 정리가 맡는다.
- spread 항목의 대상 문서는 `items`만 쓴다. 대상의 `select`(개수, 구분자)는 무시한다. 펼친 항목은 자기 `w`를 그대로 쓴다.
- 같은 문서가 여러 번 전개되면(같은 참조가 두 번, 다이아몬드 의존) 경로가 달라 문맥도 다르다. 따라서 각각 따로 뽑는다. 같은 값이 나올 수도 있다.
- **선택지 뽑기**: `T ← 보기 가중치 합`, `r ← bounded(rng, T)`, 보기를 순서대로 보며 `r < w`인 첫 보기를 고르고 아니면 `r ← r − w`. 가중치를 적지 않은 보기는 1이다. 모든 보기가 1이면 `T = 보기 수`이고 고르는 보기가 `bounded(rng, 보기 수)`와 같다. 그래서 보기 가중치 문법을 넣기 전(2026-11-03)의 결과와 같다(4.3절 성질 5). 문법이 모든 보기 0을 막으므로 `T ≥ 1`이다.
- 참조와 선택지는 `t`에서 직접 문맥을 만든다. 선택지 안에 있는 노드도 바깥 선택지의 문맥이 아니라 자기 번호로 `t`에서 만든다.

### 4.3 성질

위 절차에서 나오는 성질이다. 공통 테스트 세트 생성기가 이 성질을 검사한다(`conformance/tools/check.py`).

1. **ref 항목과 인라인 참조는 같다**: `{"ref": {"wildcard": X}}`와 `{"text": "${w:X}"}`는 같은 결과를 낸다(둘 다 `pos:0`).
2. **항목 텍스트를 고쳐도 다른 항목은 그대로다**: 뽑기는 id, w, count만 보고 텍스트는 보지 않는다. 고친 항목의 결과만 바뀐다.
3. **항목 순서는 결과와 무관하다.**
4. **하위 문서 갱신은 그 문서가 전개된 자리만 바꾼다**: lock에서 X의 해시만 바꾸면 X가 전개된 부분만 달라진다.
5. **선택지의 모든 보기에 가중치 1을 적어도 결과가 같다**: `{a|b}`와 `{1*a|1*b}`는 같다. 가중치 문법이 없던 때의 결과가 그대로라는 뜻이다.

반대로 바뀌는 것: 항목을 더하거나 빼거나 `w`나 `count`를 바꾸면 그 문서의 뽑기가 달라진다. 텍스트 안에서 노드 앞에 참조나 선택지를 더하면 그 항목 안의 뒤쪽 노드 번호가 밀려서 선택이 달라진다.

### 4.4 출력 정리 (쉼표)

참조가 0개를 뽑거나 빈 보기가 뽑히면 `1girl, , standing`처럼 빈 조각이 생긴다. 전개가 끝난 최종 문자열에 **한 번만** 다음을 적용한다.

```text
cleanup(s):
    parts ← s를 "," 로 나눈 목록          # 쉼표가 없으면 [s]
    parts에서 공백(1절)으로만 된 조각을 뺀다   # 빈 문자열 포함
    r ← 남은 조각을 "," 로 이은 것
    return r의 앞뒤 공백(1절)을 지운 것
```

- 남은 조각 안의 띄어쓰기는 바꾸지 않는다(`a,b`는 그대로 `a,b`, `a , , b`는 `a , b`). 정리하는 것은 공백뿐인 조각과 앞뒤 공백뿐이다.
- 대상은 ASCII 쉼표(U+002C)와 1절의 공백 네 글자뿐이다. 전각 쉼표(`，`), U+3000, U+00A0은 건드리지 않는다. TS의 `trim()`은 U+00A0 등도 지우므로 쓰지 않는다.
- 사용자가 텍스트에 직접 쓴 `, ,`도 정리된다. 최종 결과만 보고 출처를 구분하지 않기 때문이다.
- 중간 문서의 결과에는 적용하지 않는다. 쉼표가 아닌 구분자로 생긴 빈 조각(`a |  | b`)도 그대로다(그런 경우는 4.2절의 "빈 결과는 잇지 않는다"가 이미 막는다).
- 출처 범위(4.5절)는 정리로 지워진 글자만큼 위치를 옮겨서 돌려준다.
- 이 정리는 노드 번호, 뽑기, 하위 seed와 무관하다. 4.3절 성질은 그대로다.

### 4.5 출처 범위 (TS 전용)

편집기 미리보기의 출처 강조용이다(`DESIGN.md` 4절). 공통 테스트 세트는 비교하지 않고 TS 단위 테스트에서 본다. 뽑힌 항목마다 범위 하나 `(start, end, hash, wildcard, item)`를 낸다.

- `[start, end)`는 그 항목의 결과(`expand_item`이 낸 문자열)가 최종 문자열에서 차지하는 자리다. 위치는 UTF-16 오프셋이고 구분자는 포함하지 않는다.
- `hash`와 `wildcard`는 항목이 든 문서의 해시와 와일드카드 ID다(spread로 펼친 항목은 대상 문서). 루트 문서의 `wildcard`는 호출한 쪽이 알려 주지 않으면 `null`이다.
- 범위는 겹쳐 있다. 참조로 전개된 하위 문서의 항목 범위는 바깥 항목 범위 안에 있다. 목록은 바깥 것이 먼저다(전위 순서). 한 위치를 덮는 가장 안쪽 범위가 그 글자의 직접 출처다.
- 정리(4.4절) 뒤 위치 `x'`는 정리 전 위치 `x`보다 앞에 있는 글자 중 지워지지 않은 것의 수다. 길이가 0이 된 범위(빈 결과, 정리로 다 지워진 결과)는 버린다.

## 5. 상한과 오류

| 상한 | 값(잠정) | 넘으면 |
|---|---|---|
| `maxDepth` | 16 | `E_DEPTH` (사전 검사) |
| `maxExpansions` | 10000 | `E_BUDGET` (전개 중. `expand_doc` 호출과 spread 펼치기를 센다) |
| 선택지 중첩 | 64 | `E_NESTING` (문법) |

`maxExpansions`는 항목마다 참조를 여러 개 두고 여러 개를 뽑는 문서가 깊게 쌓여 결과가 기하급수로 커지는 것을 막는다. 공통 테스트 사례는 `limits`로 두 상한을 바꿀 수 있다.

| 코드 | 뜻 |
|---|---|
| `E_FORMAT` | 모르는 묶음 `format` |
| `E_SEED` | seed가 범위 밖 |
| `E_DOC` | 문서 스키마 위반 |
| 2.6절 코드 | 항목 텍스트 문법 오류 |
| `E_UNRESOLVED` | `lock`이나 `docs`에서 찾을 수 없는 참조 |
| `E_CYCLE` | 참조 순환 |
| `E_DEPTH` | 깊이 상한 초과 |
| `E_BUDGET` | 전개 횟수 상한 초과 |

오류가 나면 부분 결과 없이 오류 코드 하나만 낸다.

## 6. 난수와 하위 seed

모든 연산은 부호 없는 64비트 정수의 모듈러 연산이다(`mod 2^64`). TS는 BigInt, Python은 `int`에 `& (2^64 − 1)`을 쓴다.
아래 상수는 16진수다.

### 6.1 혼합 함수와 문자열 해시

```text
mix64(z):                         # SplitMix64의 출력 함수 (Stafford variant 13)
    z ← (z ⊕ (z >> 30)) × BF58476D1CE4E5B9
    z ← (z ⊕ (z >> 27)) × 94D049BB133111EB
    return z ⊕ (z >> 31)

fnv1a64(bytes):                   # FNV-1a 64비트
    h ← CBF29CE484222325
    각 바이트 b에 대해: h ← (h ⊕ b) × 00000100000001B3
    return h
```

### 6.2 하위 seed: `H(seed, 경로)`

```text
derive(s, label) = mix64(s ⊕ mix64(fnv1a64(UTF-8(label))))
H(seed, [l1, l2, …, ln]) = derive(…derive(derive(seed, l1), l2)…, ln)
```

라벨은 세 종류다. 모두 ASCII이고 숫자는 앞에 0을 붙이지 않은 10진수다.

| 라벨 | 쓰는 곳 |
|---|---|
| `item:<항목 id>` | 문서 문맥 → 항목 문맥. spread로 펼친 항목은 spread 항목 id부터 차례로 붙는다 |
| `pos:<노드 번호>` | 항목 문맥 → 참조 대상 문서의 문맥, 또는 선택지의 난수. `ref` 항목은 `pos:0` |
| `select` | 문서 문맥 → 그 문서의 뽑기 난수 |

예: 루트 문서의 항목 `p2Za` 텍스트에서 번호 1인 참조가 가리키는 문서가 다시 항목 `Xy01`을 뽑았다면, 그 항목의 문맥은
`H(seed, ["item:p2Za", "pos:1", "item:Xy01"])`이고, 그 문서의 뽑기 난수 seed는 `H(seed, ["item:p2Za", "pos:1", "select"])`다.

### 6.3 난수 생성기: SplitMix64

```text
SplitMix64(seed): state ← seed
next():  state ← state + 9E3779B97F4A7C15;  return mix64(state)
```

seed 0의 처음 세 출력은 `E220A8397B1DCDAF`, `6E789E6AA1B965F4`, `06C45D188009454F`다.

**범위 안의 정수** `bounded(rng, n)`, `1 ≤ n ≤ 2^64`:

```text
threshold ← (2^64 − n) mod n
반복: x ← rng.next(); x ≥ threshold이면 return x mod n
```

`n = 1`이어도 `next()`를 한 번 부른다. 그래서 난수를 몇 번 쓰는지가 값과 무관하게 정해진다(거절이 일어날 때 빼고. 거절 확률은 `n/2^64` 미만이다).

### 6.4 가중치 비복원 추출

```text
k번 반복:
    T ← cands의 w 합
    r ← bounded(rng, T)
    cands를 순서대로 보며: r < w이면 그 항목을 뽑고 cands에서 뺀다. 아니면 r ← r − w
```

후보는 4.2절의 key 순서로 정렬돼 있고, 한 번 뺀 뒤에도 남은 것의 순서는 유지된다. 기본 상한에서 `T`는 2^53보다 작지만(5000 × 1000000 × 전개 수), 구현은 정확한 정수 산술을 쓴다.

### 6.5 수치 표현

- seed는 JSON에서 10진수 **문자열**로 쓴다. 2^53을 넘는 seed를 JSON 숫자로 쓰면 JS에서 값이 바뀐다. ComfyUI seed 위젯의 범위가 `0 ~ 2^64 − 1`이다.
- 64비트 값을 사람이 보는 곳(테스트 벡터)에는 16진수 16자리 소문자 문자열로 쓴다.

## 7. 내용 해시

버전 ID(묶음의 `docs` 키, `lock` 값)는 문서의 내용 해시다(`DESIGN.md` 6절). 테스트 벡터는 `conformance/hash.json`.

```text
content_hash(doc) = base62_12(sha256(UTF-8(jcs(doc))))
```

입력은 3.3절 저장 형식을 통과한 문서다. 기본값을 채우지 않는다.

### 7.1 정규화 (JCS)

RFC 8785(JSON Canonicalization Scheme)를 따른다. 문서에 나오는 값(객체, 배열, 문자열, 정수, 불리언)에 대해서는 아래와 같다.

- 공백이 없다. 객체는 `{"키":값,…}`, 배열은 `[값,…]`.
- 객체의 키는 **UTF-16 코드 단위** 순으로 정렬한다(코드 포인트 순이 아니다. U+E000과 U+1F600이면 U+1F600의 앞 서로게이트 D83D가 작으므로 U+1F600이 먼저다).
- 문자열: `"`와 `\`는 `\"`, `\\`. U+0008 `\b`, U+0009 `\t`, U+000A `\n`, U+000C `\f`, U+000D `\r`. 나머지 U+0000~U+001F는 `\u00xx`(16진수 소문자 4자리). 그 밖의 글자는 이스케이프하지 않는다(`/`, U+007F, U+2028, 한글, 이모지 모두 그대로). 짝 없는 서로게이트가 있으면 정규화하지 않는다(3.3절에서 이미 거부).
- 수: 문서의 수는 모두 정수다(3.1절). 10진수로 쓰고, 앞에 0을 붙이지 않고, `-0`은 `0`이다. `3.0`, `1e2`처럼 정수값인 수는 `3`, `100`으로 쓴다. 정수가 아닌 수는 나오지 않는다(나오면 RFC 8785의 ECMAScript 수 표기를 따르지만 이 프로젝트의 구현은 거부해도 된다).
- `true`, `false`, `null`.

### 7.2 base62 앞 12자

```text
N ← sha256 결과 32바이트를 빅엔디언 부호 없는 정수로 읽은 값 (0 ≤ N < 2^256)
digits ← N을 62진법으로 쓴 것. 높은 자리부터, 숫자 d의 글자는 "0-9A-Za-z"의 d번째 (0 → "0", 10 → "A", 36 → "a", 61 → "z")
digits를 앞에 "0"을 채워 43자로 맞춘다 (62^43 > 2^256)
base62_12 ← 앞 12자
```

- 첫 글자는 `0`~`y`(0~60)만 나온다(⌊(2^256 − 1) / 62^42⌋ = 60). 앞 12자의 경우의 수는 약 2^71.43이다.
